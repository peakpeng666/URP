# 2026-10-17：主基线归档重审与统计更正

**4505 项主实验的路线质量可以重现；其中 3604 项的主机统计证明链需要补齐或降级表述。** 本次重审不调用任何优化算法，不修改原始压缩包、冻结计划或历史报告。机器可读结论见 [archive_review.json](archive_review.json)，可重复执行的方法见 [independent/audit_archives.py](../../../independent/audit_archives.py)。

## 范围与方法

主分母为 17 个配置 × 53 个问题 × 5 个种子/计时重复 × 每项 5 秒，共 4505 个计划键。三个原始结果压缩包均先按已发布的字节数和 SHA-256 验证，再解至新的临时目录。另一个 native 结果包属于独立 vendor120 对照，本次不计入主分母。

重审逐项核对计划、算例与源码身份；从原始坐标以 Decimal 80 位精度重新计算每条边的 EUC_2D 四舍五入距离，验证客户恰好服务一次、容量、车数、整数成本和截止时刻前实际收到的 incumbent。独立验算不导入求解器。另对 53 份参考解核对原始文件哈希、路线与成本，并重新计算全部可计分差距。

结果与原逐项表的 4505 行、原描述性合并汇总的 289 组逐一比较。所有摘要、工具源码哈希、分算法统计与四条中断/重试关联保存在新 JSON 中。

## 三类主机证据

| 记录范围 | 终态数 | 已归档证据 | 本次允许的解释 |
| --- | ---: | --- | --- |
| cloud，seed0，串行批次 | 901 | 最近的 host_manifest 标记 VERIFIED；计划哈希匹配，所指 environment 文件哈希一致 | 可按该已验证记录范围统计 CPU 和同机配对 |
| cloud，seed2，四路固定 CPU 批次 | 901 | 结果自报主机/资源批次；存在未标 VERIFIED、未链接环境哈希的 host_manifest | 保留自报归属和路线质量；不能标为已验证主机统计 |
| ubuntu-local，seed1/3/4 | 2703 | 结果 SHA 绑定的 FROZEN resource-manifest 均可核对，计划、源码、主机与批次字段一致；原汇总所引用的 host_manifest 包装文件未归档 | 保留已核对的资源声明链和路线质量；现有交付包不足以重现原“已验证主机/环境”统计标签 |

“已验证”在这里表示归档元数据之间的身份和哈希关系通过校验，不表示独立测量并证明了物理硬件的全部属性。本机资源 manifest 是有用证据；它与缺失的主机/环境核验包装文件承担不同责任。

原聚合代码允许自报 `host_id/resource_cohort` 直接进入“single verified host/resource cohort”，并允许结果声明覆盖 manifest 的资源批次。这会把未核验声明标成已核验执行条件。本次修复要求明确 `host_verified`：只有最近的 VERIFIED manifest 与计划、环境文件哈希一致，且没有声明冲突，才能通过。更近但未核验的 manifest 也不再继承旧父目录的认证。

| 各配置、分层的合并描述性路线质量 | 289 组 | 289 组一致 | 数值保持；继续注明异构机器与种子分配混杂 |

原配对行中，cloud seed0 为 6618，cloud seed2 为 6592；本机 b01/b03/b04/b05 分别为 13315/4842/144/1。批次不同本来就不能配对，因此这些数字不是所有有效解的任意两两组合。

当前证据不足并不证明被降级记录的路线成本或主机声明为假。需要更正的是归档可复现性和统计的证明程度。原报告已经避免跨硬件速度排名，这条限制仍然正确。若补回原核验包装文件，应校验原汇总记录的文件 SHA 与引用环境字节后重新生成**新的**派生审计；不得直接把模板改成 VERIFIED 或回填原始 result.json。

## 研究解释边界

17 个配置并非 17 个独立算法家族。冻结表中，`savings_vnd` 仅 200/265 项可行，`seeded_sweep` 为 166/265；它们的条件差距不能掩盖失败率。`savings` 和 `savings_vnd` 还使用不同的构造/容量处理过程，不能仅凭配置名把差异归因于“加 VND”。算法改进应另设版本和实验计划，原表继续作为冻结基线。

这些 CVRPLIB 结果验证的是容量约束多点路径分配与成本，不覆盖果园避障、运动学约束、覆盖完整性或仿真跟踪成功率。推荐决策模型仍需按底本分组区分训练、校准和测试；不能把这些已有历史使用记录称为未见测试集，或根据测试失败情况事后筛选候选算法。
