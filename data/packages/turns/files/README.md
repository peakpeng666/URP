# 带转向代价的任务排序与候选路径联合优化合成实验

## 结论与适用范围

本次实际运行了一个新合成基准：30 个八任务几何、5 个预先冻结的转向惩罚水平、4 个基线及精确 DP，共 750 条主实验记录，全部成功。它与单起终点 A* 测试不同，研究的是任务服务顺序和各段路径选择的共同影响。

在本候选路径模型中，先求最短距离任务顺序，再为该顺序优化转向，仍可能明显偏离长度与转向的联合目标。λ=8 和 32 时，平均相对精确最优差距分别为 8.54% 和 25.30%；转向感知 2-opt 分别为 2.31% 和 4.24%。这些是有限合成实例的描述性结果，不是实地农业效果、车辆运动学可行性、统计总体规律或 SOTA 结论。

一个重要限定是最短距离顺序可能不唯一。主实验采用事前约定的字典序打破平局。另行明确标为事后诊断的检查，在所有最短距离顺序中再选转向最少者：λ=0.5 的差距完全消失；λ=8、32 仍分别留下 5.36%、19.44% 的平均差距。因此低惩罚处的小差异应解释为等距离方案择优，高惩罚处则有真正的距离与转向折衷。

## 冻结设计

- 主协议：`freeze.json`，实验前哈希：`pre_run.sha256`。
- 主种子：2026100703；种子 = 主种子 + 100 × 几何族序号 + 重复序号。
- 几何族：均匀点、两行点、四簇点，每族 10 个独立生成实例，每实例 8 个任务。
- 同一组坐标、任务标签、起终点、路径候选在 0、0.5、2、8、32 五个 λ 下配对使用。
- 起点固定为 (0,0)，终点固定为 (20,0)。坐标是无物理单位的合成数值。
- 没有执行外部检索、模型调用、付费 API、下载、上传或凭据操作。没有使用旧项目源码或真实场地数据。
- 各算法规则和停止条件事前固定，但没有匹配相同 CPU 或相同评价次数预算。不得据此声称等预算优势。

## 任务与转向模型

单车从起点出发，以选定顺序显式服务所有任务各一次，再到终点。经过尚未服务任务的坐标不强制服务；允许路径交叉、重复经过位置和原地改变朝向的几何折角。没有容量、期限、服务成本、障碍物、最小转弯半径、车速、倒车代价或连续曲率约束。

每对相邻服务点只允许两种最短直角折线：先沿 x 再沿 y，或先沿 y 再沿 x；共线时只有直线路径。每条候选折线至多一个内部折角。本实验的“精确”仅指这一受限候选集合，不包括任意连续曲线、任意栅格路径或真实可行车辆轨迹。

目标为 J = L + λT。L 是所有非零直线段的总长度；T 是完整连续折线上相邻段的无符号航向变化，以 90° 为一单位。直行计 0，直角计 1，180° 回转计 2。计算同时覆盖每段候选路径内部的折角与两段路径在任务点的连接折角。起点没有预设航向，终点没有终端朝向要求，因此不收首尾额外角度费用。λ 的单位是每 90° 转向对应的长度单位。

三点转向依赖到达方向。单独给任务对边添加一个固定“转向费用”，通常不能正确表示这里的目标。主精确求解器保持状态 (已服务任务掩码, 最后任务, 到达航向)，而不是只保持任务节点。独立验证器直接用向量叉积和点积的 atan2 计算折线角度，不依赖主实现的 E/N/W/S 编码。

## 比较策略

1. `distance_order_fixed_paths`：用精确 Held–Karp 求最短 L1 总距离顺序，等长时取字典序最小任务序列；每段固定使用第一条候选路径。
2. `distance_order_heading_paths`：保留同一距离最优顺序，以末端航向 DP 精确选择整条路线的候选路径。策略 1 与 2 的差异隔离路径选择的影响。
3. `turn_greedy`：逐步最小化包含当前连接转向的增量目标，最后才处理终点连接；它没有全局保证。
4. `turn_2opt`：以精确距离顺序初始化，尝试所有连续子序列反转，每个候选顺序都重新优化路径选项；每轮接受严格改善的最佳反转。无改善或接受 50 次反转后停止。150 次运行均因无严格改善停止，没有命中 50 次上限。
5. `joint_dp_oracle`：精确优化顺序与路径选项，状态保留到达航向。它是本受限模型的最优参照，不作为可扩展启发式方法。

所有 DP 按已访问掩码递增处理，向尚未服务任务转移并加入候选路径长度、内部转向与连接转向，最后连接固定终点。相同状态拥有相同未来可选动作和未来成本，因此保留该状态最佳前缀满足最优子结构。复杂度量级为 O(2^n n²HK)，这里 H=4、每段 K≤2。

## 主结果

下表是 30 个配对实例的逐实例相对差距 (J策略−J最优)/J最优 的算术平均值，不是先平均 J 再求比例。

| λ | 距离顺序固定路径 | 距离顺序优化路径 | 转向贪心 | 转向 2-opt |
|---:|---:|---:|---:|---:|
| 0 | 0.00% | 0.00% | 18.09% | 0.00% |
| 0.5 | 2.44% | 0.35% | 17.21% | 0.20% |
| 2 | 8.34% | 1.36% | 14.55% | 0.77% |
| 8 | 25.99% | 8.54% | 18.51% | 2.31% |
| 32 | 54.99% | 25.30% | 22.23% | 4.24% |

精确参照各行差距均为 0。原始值、均值、中位数、最大值、严格劣于最优的数量及分几何族汇总见 `raw_results.csv`、`summary.csv`。路径选择、排序及局部搜索的预定义配对比较见 `paired_comparisons.csv`。

- λ=8 时，距离顺序优化路径在 23/30 个实例上严格劣于最优，转向 2-opt 为 10/30。
- λ=32 时，两者分别为 25/30 与 12/30；2-opt 的最大差距仍达 20.67%，不能称为总能找到最优。
- 转向贪心在多个水平上劣于距离最优顺序加路径优化。加入正确的局部转向代价本身不保证全局质量。
- 两行点族在本次高 λ 条件下的排序差距更大，但每族仅 10 个实例，未做总体显著性推断。

## 事后平局控制诊断

此诊断在查看主结果后才提出，协议单独记录于 `tie_audit_freeze.json`，代码和协议运行前哈希见 `tie_audit_pre_run.sha256`。主实验输入、源码和原始结果未作修改。

新增控制策略在全部任务顺序及候选路径上按 (L,T) 字典序精确优化，也就是“在所有总距离最短的完整方案中，再选转向最少的方案”，然后在五个 λ 下评价同一条路线。

| λ | 最短距离内最少转向策略的平均差距 | 严格差距实例数 |
|---:|---:|---:|
| 0 | 0.00% | 0/30 |
| 0.5 | 0.00% | 0/30 |
| 2 | 0.16% | 2/30 |
| 8 | 5.36% | 19/30 |
| 32 | 19.44% | 24/30 |

来源为 `tie_audit_raw.csv`、`tie_audit_summary.json`。这一控制在 6 个小规模实例上也经独立完整枚举验证。它是描述性稳健性检查，不应伪装成事前冻结的第五个主基线。

一个可复核例子为 `two_rows_07`，λ=32：即便在全部最短距离方案中优化转向，仍是 L=58、T=9、J=346；联合最优为 L=68、T=5、J=228。多走 10 个长度单位，减少 4 个 90° 等效转向单位，目标下降 118。这个例子表明目标错配不只来自任意平局规则；它没有证明真实车辆能沿这些折线行驶。

## 验证与资源记录

- 750 条主路线全部重建并复算服务任务排列、每段路径候选、折线长度、全部角度和目标值；CSV 与 JSONL 交叉检查通过。
- 独立穷举所有 30 个八任务主几何的 8! 距离顺序，共 1,209,600 个排列，确认 λ=0 的距离最优值。
- 另外 6 个五任务实例，共完整枚举 24,896 条顺序与路径组合，在 5 个 λ 下得到 124,480 次目标评价，核对 30 个小规模联合最优值，全部一致。
- 7 个解析测试覆盖直线、直角、180° 回转、跨服务点连接折角与到达方向依赖。
- 主实例正 λ 联合最优依赖经过上述验证的精确 DP，并非对八任务实例所有路径组合都重新做了完全穷举。
- 主实验及其独立检查用一个标准库 Python 进程完成：CPU 3.0289 秒、墙时 3.0330 秒；另事后诊断 CPU 0.5365 秒。独立命令行验证器也实际另跑一次并通过，详情见 `standalone_verifier.log`。累计计算远低于 180 秒 CPU 和 20 分钟墙时限制。
- 主进程 CPU 硬限 170 秒、墙时报警 1150 秒；无子计算进程。事后诊断另设 CPU 30 秒、墙时 60 秒限制。
- 并发云负载、计时分辨率以及共享距离排序预处理，使逐策略时间不适于速度排名；部分极短 CPU 时间被记为 0，不能解释为零计算成本。共享预处理 CPU/墙时在原始表单独列出，不含在逐策略时间中。
- `failures.json` 是空数组；没有筛除、替换失败实例或改种子，没有网络调用与模型 API 成本。主流程没有方案偏离；平局诊断明确列为事后新增检查。

## 文件与复现

审计时首先验证 `SHA256SUMS.txt`，再运行 `python3 verify.py`。验证器只用 Python 标准库，不导入主实验代码。它会确定性重写 `exhaustive_validation.json`，其他主原始数据不变。

建议复制目录后再完整复跑，避免覆盖原始审计文件：

```
python3 experiment.py --prepare
python3 experiment.py --run
python3 verify.py
python3 audit_ties.py
```

其中 `--prepare` 重新生成冻结几何及实验前源码/输入哈希，`--run` 执行主协议及独立验证。若只核验收到的结果，不应先运行 `--prepare` 覆盖收到的实验前哈希。

关键文件：

- `freeze.json`、`pre_run.sha256`：事前协议和源码/输入冻结摘要
- `experiment.py`：生成器、四基线与精确求解器
- `instances.json`、`validation_instances.json`：主几何与正确性几何
- `routes.jsonl`：750 条完整路线、服务顺序、候选索引、折线、航向与运行时间
- `raw_results.csv`：逐实例、逐 λ、逐策略指标与精确差距
- `summary.csv`、`paired_comparisons.csv`：预定义汇总与配对比较
- `verify.py`、`verification.json`、`validation_dp_results.json`、`exhaustive_validation.json`：独立验证源码与证据
- `run.log`、`run_status.json`、`failures.json`、`standalone_verifier.log`：执行、资源、失败与独立复跑记录
- `tie_audit_freeze.json`、`tie_audit_pre_run.sha256`、`audit_ties.py`、`tie_audit_raw.csv`、`tie_audit_summary.json`、`tie_audit.log`：明确标识的事后平局控制
- `SHA256SUMS.txt`：交付文件校验清单

这些结果支持继续把“目标一致的排序与路径联合优化”作为研究检查项，但尚不足以证明真实农业任务收益、处理障碍物的能力、规模扩展性能或车辆动态可行性。下一阶段若纳入真实运动约束或扩大任务规模，应另行冻结模型、实例与公平预算，不能把本次小规模精确结果直接外推。
