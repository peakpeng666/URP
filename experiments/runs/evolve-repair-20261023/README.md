# evolve-repair-20261023：回路②候选成员（局部 Dubins 修补）的准入实验

目的：回答「向覆盖配置库加入**局部 Dubins 修补**成员能否提升实际策略」，即[持续进化决策与调度](../../../docs/持续进化决策与调度.md)回路②的第一个候选准入实验。候选实现为 `src/lab/urp_lab/evolve/repair.py`：原样重放 Fields2Cover 全流程，在每个曲率缺陷（官方检查口径）附近用窗口内最短前进 Dubins 路径替换，窗口不进入作业行；修补后的路径**只经未修改的官方 `check_path` 判定**。本目录只含开发数据（荷兰 140 块），与主审计 `evolve-audit-20261023` 使用同一批准入实例。

## 配置与排除

- 候选配置：`repair:` 前缀 = 不分解、牛耕分解 × {最少作业行、作业行最短、覆盖最大}，共 6 个；转弯模型与主审计一致为 Dubins（前进）。算法标识 `evolve.f2c_repair`（研究候选，不在注册算法目录中，由 `evolve.sweep.solve` 分发）。
- **梯形分解不纳入**：主审计中梯形分解大量超时（300 s 上限）且可行率极低（见主审计 README「结果」的失败分类），修补无法挽救「分解本身不收敛/不可行」的配置；纳入只会增加无效计算。
- 单区适配器（`single:*`）不修补：其失败模式是「仅支持单个凸内缩区」等结构性拒绝，局部曲率修补不适用（主审计失败分类中 `single_cell_only` 与曲率无关）。
- 实例集合：与主审计完全相同的 388 个（140 块荷兰田 × 3 机具，几何准入排除 32 个）；每项墙钟上限 300 s，超时/崩溃/无解都计入分母，不重试。

## 执行

- 冻结计划：`plan.json`（SHA-256 `4db3b7c36e0abefad7061e45cc25235e232b5c05022517abdf7db66f7c07d92a`，见 `plan.sha256`）；运行命令与主审计相同（`--workers 16 --cores 8-23`）。
- 准入分析：`admission/admission.json`，由 `admission.write(主审计目录, 本目录, library=主审计 11 配置, candidates=本目录 6 配置)` 生成；四种准入依据（单成员成绩、VBS 增量、实际策略收益、Shapley）与五个对照（旧库策略、训练 SBS、新成员单独、新库 VBS、新库实际策略）。VBS 只作上界。
- 严格重验证：`reverify/` 对本目录可行路径同样做确定性重算与 2 cm 加密曲率敏感性分析。
- 原始逐项记录与逐条重验证 JSON 打包为 `../../results/进化决策/evolve-repair-20261023-records.zip` 与 `evolve-repair-20261023-reverify.zip`（SHA-256 见同目录 `SHA256SUMS.txt`）；本目录内为同批原始文件。

## 结果

2328 项全部终态：可行 1999、无解 314、超时 15。准入分析与解读见[审计报告 §5](../../reports/进化决策/农业组合互补性审计与覆盖尝试顺序.md)；要点（官方判定，与主审计相同的 388 实例）：

- **单成员**：修补·不分解·覆盖最大可行 **380/388（97.9%）**、修补·不分解·最少作业行 357（92.0%）、修补·牛耕·最少作业行 335（86.3%）；均超过原库最好成员（不分解·最少作业行 326，84.0%）。
- **四项准入信号**（`admission/admission.json`，分母为扩展库可解的 384 实例）：单成员如上；VBS 384/388（原库 373，+11 实例）、余量增量 0.032；实际策略收益（留出田块交叉验证）静态顺序首选可行率 0.849 → 0.930（+0.081）、平均尝试 1.45 → 1.08，logit·农业特征 0.836 → 0.954；Shapley 前两位为修补·不分解·最少作业行（0.115）与修补·不分解·覆盖最大（0.113）。四项一致支持准入；VBS 数字只作上界。
- **严格曲率敏感性（`reverify/`）**：1985/1999 重算哈希一致；14 条不一致全部在牛耕分解配置（不分解配置 0 条）——非确定性来自 Fields2Cover 的分解步骤（与主审计的梯形分解非确定性同类），修补步骤本身可复现。严格判定下修补路径的盲区率仍为 29–62%（修补·不分解·覆盖最大最低，111/380 = 29%，严格可行约 269/388）：**修补只修复官方检查可见的曲率缺陷，长弦拐角盲区需检查器改进（对接需求第 14 项）或候选侧加密判定**。准入结论以官方判定为准，严格数字为边界说明。
- 结论属性：开发侧；封存测试田块未运行。
