# evolve-repair2-20261024：修补 v2 的正式扫描（开发侧）

目的：第 2 轮任务 T5 的正式评价。修补 v2（`src/lab/urp_lab/evolve/repair2.py`，实现提交见 `plan.json` 的代码身份）在修补 v1 的基础上同时处理两类缺陷：官方检查可见的三点曲率缺陷，以及倒圆判定揭示的**不可倒圆拐角**（相邻拐角过近、拐角邻接转弯采样段）。每处目标用沿非作业行段最多 1/2/4/8 个转弯半径窗口内的最短前进 Dubins 路径替换（作业行不被切开）；无法修复的目标按位置记忆以避免死循环；最后对剩余拐角做半径 r 倒圆，倒圆后的路径（作业行按切线长截短并重新声明）必须通过**未修改的**官方 `check_path`。

- 配置：`repair2:` 前缀 = {不分解、牛耕分解} × {最少作业行、作业行最短、覆盖最大}，共 6 个；转弯模型 Dubins（前进）。算法标识 `evolve.f2c_repair2`（研究候选，不在工作台注册算法目录中，由 `evolve.sweep.solve` 分发）。
- 实例：与主审计、修补 v1 完全相同的 388 个（荷兰 140 块田 × 3 机具，几何准入排除 32 个）；不纳入梯形分解与单区适配器，理由同修补 v1（分解本身不收敛/结构性拒绝，局部修补不适用）。
- 计划：冻结计划 `plan.json`，SHA-256 `12b0dbd8a28031475a2658862bff67705fb7c18eb30d095fddcbd2928404f161`（见 `plan.sha256`）；能效核 8–23、16 进程、每项墙钟上限 300 s，终态只记一次，不重试不择优。
- 之后对官方可行路径做倒圆判定（`fillet/`，5 次重跑内必须再现记录路径哈希，否则标为无法核验）。
- 分析：把 6 个 `repair2:` 配置并入扩展库，按官方/倒圆/严格三种判定重跑 `verdicts.write`；准入分析把修补 v2 作为候选池（旧库 + 修补 v1 为基础库）重跑 `admission_rules.write`，单独登记、不覆盖原结果。
