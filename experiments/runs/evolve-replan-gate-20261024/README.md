# evolve-replan-gate-20261024：学习「何时重排」的门控（调度回路的学习，规划层仿真）

动机：动态调度研究（[evolve-dynamic-20261024](../evolve-dynamic-20261024/README.md)）发现，只用过去信息的 rollout 仅在 1.7%–18% 的决策点采用重排，结果却与每次都重排几乎相同；但 rollout 每次都要调用求解器。本运行学习一个门控，只在可能需要时才调用求解器。

方法（`src/lab/urp_lab/evolve/replan_gate.py`）：

- **老师**：在与动态研究相同的 180 条流上重跑 rollout，记录每个决策点求解前即可得到的调度状态特征（`dynamic.FEATURES`：待服务任务数、人均待服务数、负载不均、插入代价的相对值与尺度化值、离上次重排的决策数、上次重排后插入数及占比、待服务任务的空间离散度、班次进度），以及 rollout 是否选择重排。
- **学生**：L2 逻辑回归。阈值在训练田块上选定，保证对老师所选重排的召回率 ≥ 0.8。
- **评价**：按田块分 5 折，门控只用其他田块的决策训练；在留出田块的流上运行「门控为真才调用求解器并重排」，与动态研究中同一流的只插入、每次重排、rollout 结果配对比较，指标为里程、平均响应和求解器调用次数。
- **范围**：规划层离散事件仿真，恒速时间模型，单一随机种子（7），自由通行。

## 结果

2026-10-23 在性能核 0–3 上运行（4 进程）：180 条流的决策全部采集，每折训练集 4320 个决策，其中前瞻采样选择重优化的比例为 12.1%–13.9%；各折阈值 τ = 0.132–0.154。评估为 180 条留出流，汇总见 `summary.json`。

**结论**

1. 学习型重规划触发器在留出田块上复现了前瞻采样教师：6 个场景中平均响应时间与教师之差的 95% 置信区间均包含 0，而求解器调用减少 16.6%–93.7%。
2. 节省随到达密度递减：稀疏流中重优化很少有益，触发器只在约 2 个决策点调用求解器（减少 94%）；密集流中重优化本身频繁有益，节省 17%–21%。
3. 相对逐事件重优化，平均响应时间差为 −0.8% 至 +2.8%（置信区间均含 0），总里程增加 0–1.9%，其中中等 · 2 车显著（+1.9% [+0.2, +4.0]）。密集 · 4 车跳过的 20.7% 调用与逐事件重优化结果完全一致，说明这些决策点上重优化不改变方案。
4. 调度回路由此得到一个可学习、可解释（10 个求解前状态特征的逻辑回归）的「何时重规划」策略；召回率目标决定质量与计算量的权衡，可按场景调整。
