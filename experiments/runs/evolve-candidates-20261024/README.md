# evolve-candidates-20261024：准入依据研究的候选池（开发侧）

目的：给第 2 轮任务 T4（哪种准入依据能建出更好的算法库）提供相互冲突的候选。基础库为主审计的 11 个覆盖配置，候选池为修补 v1 的 6 个配置（`evolve-repair-20261023`）加本运行的 8 个新候选（`urp_lab/evolve/candidates.py`，研究代码，非工作台注册算法）：

- 修补窗口变体 4 个：半窗 (0.5, 1, 2) r 与 (2, 4, 8, 16) r × {不分解·最少作业行、不分解·覆盖最大}；
- 牛耕分割角变体 2 个：分割角 0.25π、0.75π（默认 0.5π）× 最少作业行；
- 倒圆输出变体 2 个：全流程后做半径 r 倒圆（偏离容差 1 cm），可倒圆时输出倒圆路径 × {最少作业行、覆盖最大}。

实例与主审计相同（荷兰 140 块田 × 3 机具，几何准入后 388 个）；冻结计划 3104 项，SHA-256 `4e6db2fa…`（见 `plan.sha256`）；能效核 8–23、16 进程、超时 300 s，终态只记一次。之后对可行路径做倒圆判定（`fillet/`）。分析代码：`urp_lab/evolve/admission_rules.py`（嵌套、按田块分组；规则只用外层训练田块选择成员）。

L0 等额多试对照（只增加尝试次数、不换库）：官方判定下「最多 3 次」首选 0.9345、「最多 5 次」0.9702；倒圆判定下 0.9298 / 0.9369。也就是说，官方判定下 R1 的首选（0.9345）恰好等于旧库多试 3 次，R2/R3/R4 的 0.985 才超过它；倒圆判定下信号规则的首选 0.9429 只比旧库多试 5 次（0.9369）高 0.6 pp。**新成员的多数价值是把重试变成首选成功，而不是创造原本无解的实例**；它降低的是尝试次数与停止成本的不确定性。

规则两两比较（逐田块配对，双侧 Wilcoxon，Holm 校正；`pairwise.families`）：

- **官方判定、m=1**：R2/R3/R4 的首选比 R1 高 5.0–5.1 pp（Holm p = 0.0074），但停止成本比高 7.3–7.4 pp（Holm p < 10⁻¹⁴）。以可行率为目标的规则确实收进了成本更高的成员。
- **官方判定、m=1、相对 L0**：R1 +8.8 pp [+5.9, +12.2] 且成本 −2.0 pp [−3.5, −0.8]；R2/R3/R4 +13.9 pp 但成本 +5.4 pp；随机 +5.4 pp、成本 +0.6 pp。
- **倒圆判定、m=1**：四条信号规则选出**同一个成员**（`repair:none/field_coverage`），首选比 L0 高 16.4 pp [11.2, 21.9]、成本 +1.5 pp [−2.1, +4.5]（区间含 0）；随机只高 2.0 pp、成本 −1.0 pp。规则之间没有分歧，也没有「以可行率为目标就必然更贵」的证据。
- **成员选择分歧**：官方判定下 R1 与 R3/R4 的 top-2 集合 Jaccard = 0，与 R2 = 0.33；倒圆判定下四条规则 m=1 的 Jaccard = 1。规则目标对库的影响只在宽松判定下显现，倒圆判定把选择收敛到同一个物理上可执行的成员。

结论：

1. **「以可行率为目标的规则会收进成本更高的成员」在官方判定下成立**：R2/R3/R4 选 `repairw:none/field_coverage@2-4-8-16`，首选 0.985–0.986，但停止成本比 1.099，比 R1 高 7.4 pp（Holm p < 10⁻¹⁴）。**在倒圆判定下不成立**：所有信号规则都选 `repair:none/field_coverage`，首选 0.943、成本 1.090，成本溢价与 0 不可区分。
2. **随机加入不是合格替代**：官方 m=4 时随机尚可（0.943 / 1.041），但倒圆判定下只有 0.834，显著低于信号规则的 0.943，且平均尝试 1.5 次（信号规则 1.10）。
3. **相对「等额多试」**：新库的首选收益大部分可由旧库多试 2–4 次达到；新成员的真正价值是减少尝试次数与停止成本的不确定性。若部署目标是「一次成功」，准入应继续；若目标是「最终可行」，旧库加回退已接近。
4. **判定选择决定准入结论**：官方判定给出「可行率 vs 成本」的规则分歧，倒圆判定给出无分歧的高可行成员。这与 §7.4 的结论一致：宽松判定会奖励「官方可行但不可倒圆」的配置，把成本转嫁给执行侧。
5. 证据边界：开发侧（荷兰 140 块田）；修补候选不是注册算法；封存测试未运行。完整区间、选择频率与两两比较在 `admission/admission_rules.json`。
