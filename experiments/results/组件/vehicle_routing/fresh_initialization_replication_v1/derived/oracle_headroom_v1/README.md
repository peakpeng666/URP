# 开发集事后 oracle：当前库还剩多少选择空间？

**当前三个配置的剩余质量空间很小：相对始终使用 warm PyVRP，理想的逐实例选择平均仅再改善 0.02672%（0.25 s）或 0.03016%（1 s）。** 这是看到结果后计算的开发集 oracle，不是可执行选择器、统计置信界或泛化保证。

## 聚合与定义

仅使用既有 `runs/dev_20261004_01/results.json` 的 **600 条主运行**。全部可行且满足预算；20 个基础实例均保留，没有删除失败来改善比较。每个实例、配置和预算先平均原始未取整距离的 **5 个 seeds**，随后对 20 个实例等权汇总。先平均 seeds，再挑实例最优配置；没有逐 seed 选优，也没有混入 120 条重放或 8 条诊断。

- 最佳固定配置：在同一 CPU 上限下，使 20 个实例平均距离最低的一个配置
- 逐实例 oracle：每个实例三个五-seed 均值中的最小值
- 绝对 regret：固定配置距离减去 oracle 距离，单位是原坐标距离
- 相对 regret：每个实例的绝对 regret 除以该实例 oracle 距离，再对实例平均
- 可恢复改善：同一差值除以固定配置距离，再对实例平均；分母与相对 regret 不同

最佳固定配置在两个预算下均为 **savings-warm PyVRP**。改用“平均相对 oracle regret”来选择固定配置，结论也相同。固定配置自身也是事后从本批数据选定。

## 如何使用这个结果

观察到的约 **0.03%** 平均空间，以及零中位 gap，不足以单独支持现在投入选择器训练。理想 oracle 已假设免费知道所有配置的结果；实际训练误差、选错、特征提取和决策开销都可能进一步消耗可兑现收益。本分析没有给质量和 CPU 之间设定未经用户批准的效用函数，也未证明任何实际策略会得到净收益。

计时停止搜索有波动：既有选定重放为 109/120 精确一致，warm/random 的单-seed 比较方向有变化。它不能作为五-seed 均值的独立复验；本表也不能据此声称微小 oracle gap 稳定。20 个实例均为定向开发样本，仍可能有事后最小值选择的乐观偏差。

较合理的下一步是先完成已安排的 **OR-Tools 新家族对照**，再判断是否增加了具有实际意义的选择空间。本分析没有训练选择器、基于这些结果调整库，或接触正式最终 holdout；H1/H2 仍未获得证明。
