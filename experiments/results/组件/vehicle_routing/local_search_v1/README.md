**已完成：360 次配对求解，360 次独立验收通过，360 次重放精确一致。成熟求解器强基线门槛仍未完成。**

**勘误：独立复核发现 15 次 work-cap 调用存在一次 generator look-ahead，实际计算 100,001 个 delta，原计数 100,000 是准许比较的数量。原始证据保留不变，详见 [ERRATUM.md](ERRATUM.md)；修正版另存于 `../local_search_v2/`。**

本轮在原来的 24 个合成开发实例上新增可行局部搜索，实际运行而非只补计划。所有旧实例、旧结果和原模块保持原哈希；未读取、生成或评测最终 holdout。没有新安装包，没有付费或实验侧模型 API，没有使用用户电脑。

## 实际结果

每个方法运行 24 实例 × 3 seeds = 72 次。比较先对每个基础实例的三次 seed 成本求均值，再对 24 个实例等权汇总相对降幅；seed 重复不是额外独立样本。

| 配对比较 | 平均路线长度下降 | 中位数 | 更好 / 相同 / 更差（实例） |
|---|---:|---:|---:|
| savings + VND 相对原 savings | 0.4396% | 0.1364% | 14 / 10 / 0 |
| 多起点 VND 相对单起点 VND | 0.7124% | 0.0000% | 10 / 14 / 0 |

两行具有不同的分母，不能直接相加作为总相对降幅。两种 VND 是**同一局部搜索家族的配置**，不是两个独立算法家族。多起点包含单起点的起始搜索，因此没有退步不是独立互补性的证据。

| 方法 | 平均 solver CPU | 平均完整子进程 CPU | 平均单次总 wall |
|---|---:|---:|---:|
| 最近邻 | 0.205 ms | 41.031 ms | 42.304 ms |
| 原 savings | 0.392 ms | 41.193 ms | 42.568 ms |
| seeded sweep | 0.179 ms | 41.080 ms | 42.323 ms |
| savings + VND | 1.537 ms | 42.222 ms | 43.501 ms |
| 多起点 VND | 32.085 ms | 74.171 ms | 75.510 ms |

多起点为额外 0.7124% 的开发集距离收益付出了约 **20.88 倍 solver CPU**；完整子进程 CPU 的比例较小，因为解释器启动等固定开销占比很高。这里没有人为指定质量/时间的兑换权重，也没有证明实际选择策略的净收益。

按分布和规模分组的平均降幅：

| 分组（各 4 个实例） | savings + VND vs savings | 多起点 vs 单起点 VND |
|---|---:|---:|
| uniform, n=8 | 0.0000% | 0.0000% |
| uniform, n=20 | 0.3627% | 1.4370% |
| uniform, n=40 | 0.9376% | 1.7629% |
| clustered, n=8 | 0.0000% | 0.0000% |
| clustered, n=20 | 0.1952% | 0.0783% |
| clustered, n=40 | 1.1422% | 0.9960% |

这是开发数据的描述性结果，不能解释为显著性、分布外泛化或已达到最优值。n=8 无提升本身不证明构造解全局最优。

## 固定算法与预算

- `savings_vnd`：savings 初始化；按 2-opt → relocate → swap → 2-opt* 做 best-improvement VND；改进后回到首个邻域
- `multistart_vnd`：同样的搜索，从 savings、最近邻和十个 seeded sweep 起点出发，保留最好的完整可行解
- 每次调用一致的 0.25 秒合作式 solver CPU 上限、1 秒完整 worker wall 上限
- VND 每次调用共享 100,000 次可行 move-delta 评估上限，多起点不把预算逐起点重置
- 同一 instance/seed 内随机化方法执行顺序，所有顺序在首个调用前冻结；全部串行
- 单起点 72/72 完成声明邻域的局部最优搜索；多起点 57/72 完成全部起点，15/72 到达 work cap 后返回 incumbent
- 本批没有 CPU 超额、wall timeout 或自然失败；人为注入的测试故障不计入这 360 次

完整预先固定协议见 [PROTOCOL.md](PROTOCOL.md) 和 [protocol.json](protocol.json)。新增求解器是为标准基线编写的透明实现，并非复现成熟库，也不是完成了 P3/P5 的候选生成、筛选、谱系与模型费用实验。

## 成本边界

本批 wall **17.795 秒**，父进程 CPU **0.632 秒**，完整子进程 CPU 合计 **17.258 秒**，二者不重叠的 CPU 和为 **17.890 秒**。solver CPU 合计只有 **2.477 秒**，不能拿它冒充完整运行成本。

Linux `wait4` 补入了原 pilot 漏掉的解释器启动、导入、输入验证、序列化和退出 CPU，包括超时被杀的子进程。独立重放另花 wall **17.276 秒**、父 CPU **0.576 秒**、子 CPU **16.752 秒**，单独记录，未混入主批。

上述 batch 费用不含开发代码、预检测试、冻结文件、最终聚合写盘、后续分析、助手/人工劳动或平台订阅费。API 调用为 0；不能据此声称整项研究免费。硬件为此次云端 Debian/Python 环境，未验证 Ubuntu 22.04。协作式 CPU 限额一般可能微小超时，虽本批未发生；wrapper 也不是不可信程序安全沙箱。
