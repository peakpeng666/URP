# P3 在线装箱：First Fit / Best Fit 开发先导

**已实际完成标准基线、在线接口、独立验收及一轮开发实验；没有复现 EoH，没有 LLM 生成候选或进化搜索，不能记为老师 P3 全部完成。**

本目录独立于排序代码生成实验，未执行任何模型生成程序。全部实验在既有云端以 Python 标准库执行，无安装、外部模型 API、付费模型调用或用户电脑操作。实际环境 Debian 13.6、Python 3.12.14，尚未验证 Ubuntu 22.04。

## 真实结果

主运行 `results/pilot_20261004/`：6 个开发分布族 × 3 个序列长度（100/500/1000）× 20 个实例，共 **360 条独立 seed 的开发到达序列，FF/BF 合计 720 次运行**。每算法每序列只跑一次，没有把确定性复验计为新样本。

- 720/720 次通过独立可行性、箱数与负载验收，0 次自然运行失败
- 配对 BF 胜 160、FF 胜 2、平局 198；BF 每序列平均少 1.3806 箱，平均配对降幅 0.5604%
- 这是对这批手选分布和长度的等权描述性汇总，不是普遍优越性或正式测试结论
- 前后各 27 个 unittest 方法通过，含无预读与前缀不变性检查、任意精度整数、10 个故障注入、独立分区枚举对照；其中 oracle 枚举核对穷尽了 4^5=1024 个五物品输入
- 另有 30 条 n=12 的验证序列：60 个基线解均不低于精确离线最优值，且下界不高于最优值
- 全部保存的 720 个解再验收、再逐项确定性重放，30 个微型 oracle 再计算，CSV/JSON/源码与数据哈希复核共 16,494 个断言通过。复验额外计算不计为新增实验样本

统计定义：主效应为每条配对序列的 FF 箱数减 BF 箱数，再求均值；正值有利 BF。次效应为每条序列 `100*(FF-BF)/FF` 再求均值，**不是整体均值之比**。各格用冻结 seed 做 5000 次配对 bootstrap、线性插值百分位区间，未作多重性校正，不报确认性 p 值。汇总全分布的一个均值会掩盖规模与分布差异。

互补两阶段构造提供一个重要负面结果：每个小物品恰有一个补齐容量的大物品，所以已知离线最优值为 n/2。BF 在这 60 条序列上平均仍比该最优值多约 42.29% 箱；FF 约多 42.31%。两算法彼此接近不等于接近最优。该结论仅属于本次特殊到达构造，不能代替一般竞争比证明。

## 问题与真正在线接口

- 箱容量固定为正整数 1000；物品为 1..1000 的正整数，不允许零、负、浮点或 bool。空到达序列合法，使用 0 箱
- 目标仅为非空箱数，箱供应无限，不设每箱额外成本、时间窗、二维几何或其他约束
- 到达顺序不可改，已经放入的物品不可移动，不允许提前排序或离线装箱
- `run_online(items_iterator, capacity, policy)` 只取一个物品，调用 policy，提交该物品的不可撤销分配，然后才请求下一个
- policy 每次只收到当前物品大小与按开箱顺序排列的既有箱剩余容量不可变 tuple。它看不到未来物品、总长度、分布名称、seed、oracle 或最优值
- FF 选按开箱顺序的第一个可放箱；BF 选可放箱中剩余空间最小者，平局选最先开箱者。没有可放箱才开一个新箱
- 箱编号按首次开箱顺序连续递增；所有已开箱始终可放。所有容量和箱数使用 Python 整数精确比较，没有浮点容差

这个接口和已审查的两份源码保证本次基线的因果实现；它不是安全隔离环境，不能防止恶意插件使用全局状态或外部通道，**禁止把它直接用于运行 LLM 生成程序**。排序任务的隔离阻塞没有被绕过。

## 独立 checker、下界与 oracle

`obp/checker.py` 不导入基线、控制器或 oracle；直接从原始到达物品与每物品箱编号重新计算所有负载、箱数、剩余空间。检查覆盖物品数、整数类型、标签顺序、容量溢出、伪造箱数和伪造负载。

下界取以下两者最大值：总物品大小/容量的向上取整，以及大于半容量的物品个数。仅当可行解箱数恰等于下界才证明该实例最优；**“超出下界多少”一般不是最优性差距**。例如容量 10 的五个大小 4 物品，下界为 2，但真正最优为 3。

`obp/exact.py` 用子集 DP 穷尽各子集最少箱数与最后一箱最小负载，最多 16 个物品，供独立微型离线 oracle。它允许重排，不能作为在线基线；没有参与主实验解生成。测试另用独立递归分区枚举验证 oracle，而不是用基线输出冒充真值。

10 个数据级故障注入全部按预期拒绝：漏/多物品、溢出、提前引用未开箱、负标签、虚报成本、虚报负载、bool 标签、浮点物品及 bool 容量。它们与自然失败分开统计。最初从 URP 上层目录错误调用 unittest 导致 import 路径错误；该工程调用错误保留在 `logs/initial_invocation_error.json`，切换正确工作目录后通过，没有安装依赖或删改基线失败样本。

## 数据冻结与六种到达分布

在任何主开发 solver 调用前保存全部序列、内容哈希、配置和本目录 Python 源码快照；该记录只是本地预冻结，不是公开预注册。主 seed 规则：202610040000 + family_index×10000 + length_index×100 + replicate，各格 replicate=0..19。微型验证采用独立 seed 202610140000 + family_index×100 + replicate，replicate=0..4；这些数值仅是验证 seed，未保留为正式测试。

- `uniform_full`：逐物品独立整数均匀 U[1,1000]
- `uniform_small`：逐物品独立整数均匀 U[1,300]
- `uniform_large`：逐物品独立整数均匀 U[501,1000]，每物品必占一箱，提供已知最优边界核验
- `bimodal`：每物品等概率从 U[100,300] 或 U[700,900] 取整数
- `boundary_discrete`：逐物品等概率取 {249,251,333,334,499,501,666,667,751}
- `complementary_phases`：先生成 n/2 个 U[251,499] 小物品，再将其逐个 1000-大小的互补物品随机打乱后接在后半段。此族有阶段相关性，不是 iid，也不是事后改变基线收到的顺序

所有物品与到达顺序对 FF/BF 完全相同。Python `random.Random`、seed、实际 Python 版本和物化后的序列均保留，复现优先以保存序列为准。没有生成、访问或筛选正式测试集；生成入口只接受 development split，微型验证也不作为正式测试。防误用检查不是盲测安全边界。

这六种分布是自定义教学开发设计，**不是 EoH 论文的原始 benchmark 协议**。不应把它们的结果与 EoH 论文表格作直接数值比较。

## 实际成本与可复现证据

主运行包含数据落盘、720 次基线、检查、统计与微型 oracle：记录到 summary 写完的 wall 约 2.867 秒、进程 CPU 约 2.863 秒；其中基线阶段 CPU 合计约 2.010 秒。独立复验另用 wall 约 2.864 秒、CPU 约 2.859 秒，前后测试另记录。主运行 Linux 进程峰值 RSS 为 47,116 KiB，复验为 60,620 KiB，包含解释器和保存数据，不是算法独占内存。

FF 记录 39,501,152 次既有箱检查，BF 41,183,979 次；这些是本实现确定性算法工作量，未计 tuple 复制、控制器、检查器及 I/O。所有 n≤1000，每次至多 n(n−1)/2=499,500 次 policy 箱检查。该有限工作量合同不是强制超时沙箱。测时包含输入验证和控制器，不包含 checker；云端负载未受控，不能据单次 wall 判断速度优劣。外部 API 调用和费用为 0，云计算实际货币费用不可获得，不声称计算免费。

主要文件：

- `config.json`：预先指定分布、规模、seed、算法、效应量与统计参数
- `obp/`：手写基线、在线控制器、独立 checker、数据生成、微型 oracle、统计
- `tests/test_online_packing.py`：27 个测试方法及独立分区枚举
- `results/pilot_20261004/sequences.jsonl`：360 条主开发完整到达序列
- `results/pilot_20261004/runs.jsonl`：720 个逐物品分配、独立复算、状态和成本记录
- `results/pilot_20261004/runs.csv`：可排序的每运行摘要
- `results/pilot_20261004/paired_effects.json`：18 个格子的配对效应量和区间
- `results/pilot_20261004/tiny_sequences.jsonl`、`tiny_oracle_checks.json`：独立的 30 条验证输入与 60 个解
- `results/pilot_20261004/freeze.json`、`source_snapshot/`、`artifact_manifest.json`：冻结证据、源码快照与产物哈希
- `results/pilot_20261004/{environment,costs,failures,failure_probes,summary}.json`：环境、成本、自然失败、故意失败及摘要
- `results/verification_20261004.json`：保存解重验、精确重放、重算统计与哈希核验
- `logs/`：前后测试和真实执行输出；所有新运行与新复验输出均拒绝覆盖旧文件

从本目录执行：

```sh
python3 run_tests.py --output logs/tests_new_round
python3 verify_artifacts.py --input results/pilot_20261004 --output results/verification_new_round.json
python3 run_experiment.py --output results/reproduction_new_round
```

复现需使用全新的目标目录/文件。源码与冻结版本有变时，验证器会拒绝当前源码重放；可在独立可写位置使用该运行保存的完整 `source_snapshot/` 复现。对照箱数、分配、物品序列和确定性统计，不比较时间戳、wall/CPU 或进程 ID。
