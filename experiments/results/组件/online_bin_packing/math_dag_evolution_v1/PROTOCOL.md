# 两代受限 DAG 机制对照：前瞻准备

状态：协议与手写验证准备。正式模型生成和候选评分尚未放行。独立的固定 JSON-schema 接口烟测另有一次授权，不计作设计候选，也不使用任何实验实例。

## 问题与范围

检验在同一小型本地模型、同一受限语言和同一初始种子池下，带父代及设计集反馈的两代修改，是否在这个固定小面板上优于独立生成。仅有一对搜索过程；没有独立重复、显著性检验或普遍优势主张。22 次机会不等于相同实际 tokens/CPU；按共享初始化、演化臂、对照臂、评分和准备阶段分别记账。

这是受限数学 DAG、短序列、固定 FF/BF 种子的小型教学变体。它不是 EoH 原 GPT-3.5、完整 Python 候选空间、5000 物品、20 代的复现。本地固定身份为官方 Qwen3-4B-GGUF Q4_K_M 与 llama.cpp b11387；GGUF 内嵌 Instruct-awq 标签差异仍未解释，保存原字段，不改称其它模型。

## 22 个真实请求与共同种子

物理请求为 2 次共享 I1 初始化，演化臂 2 代×5 算子各1次，共10次；独立生成臂10次。每臂描述性分母12，包含相同的2个共享请求，不把它们算作4次物理调用。

每个操作槽与同代独立生成槽共用一个预先固定 seed。相邻配对交替先演化/先对照，完整顺序在 protocol.json。初始两个 seed 与后续十个配对 seed 也已固定。不同提示下相同 seed 不是相同采样轨迹，配对不是独立重复。

两臂始终拥有相同的可信手写 FF、BF 图，见 seeds/。共享初始化输出加入两个共同种子之后，按设计集选择2个不同图表示作为初始父代。没有结果后临时注入、手改、修补、重试或补足调用。已发表公式不作种子、提示示例或选择成员，仅在两个赢家承诺之后作固定参照。

种子本身若在固定解释器或独立可行性检查中失败，视为基础设施异常并停止，不以其它策略顶替。原则上 FF/BF 提供两个不同的图表示；若任一选择点不足两个合格、不同图表示，停止整个配对研究，保留未运行槽位。

## 选择、更新与重复

合格要求四个设计案例均有完整、有限且独立可行的装箱结果。主适应度是精确有理数 (sum bins − sum L1)/sum L1，越小越好；L1 只是体积下界，不是最优箱数。以总箱数再按固定来源顺序打破平局：FF、BF、两个初始化、随后请求表顺序。固定案例共同分母使第二个键冗余，但显式保留。

每代开始时保存一个 N=2 的父代快照。E1/E2 用两个父代，最优者在前；M1/M3 用最优父代；M2 用第二父代。该代五个操作不使用同代刚产生的结果。五个配对都完成后，演化臂从旧父代和五个新输出中保留最好的两个不同图表示。对照臂保留累计最优两个，但其提示从不包含父代、适应度或其它生成结果。

图表示身份使用有序节点、返回节点及类型化常数，不包含 description；f64 以 binary64 hex 规范化并区分有符号零。死节点、常数索引和运算次序均保留。它不是数学等价判定，也不证明策略多样性。每个重复生成记录仍占原分母、仍进行自己的设计评分，只是不占第二个同身份父代位置。完整的同身份确定性结果若冲突，停止为基础设施不一致，不取较好一次。

## 高层说明与算子报告

description 仅需一句公开启发式说明，不索取推理过程。所有模型内容只作为受限 JSON 数据；候选不作为 Python 执行。父代提示使用固定、无截断的 JSON 表示，原始内容一直保留；其中尖括号以 JSON Unicode 转义表示，避免 description 伪造聊天模板标记。这不是对候选逻辑的修复。

提示要求某算子不等于实际遵循该算子。记录节点数、运算/引用/返回节点变化、常数类型与值变化；M2 的“仅参数修改”是一个明确结构标记，M3 的“节点变短”也只是结构观察。一节点 BF 无更短合法图，重复或无操作仍是有效观察，不能补抽。E1/E2 的创新或共性采用不自动成立。

另记录四个完整设计案例的分配签名，用于区分“不同图表示”与“这个面板上观察到不同装箱行为”。相同签名不是普遍等价；不同语法也不是新算法。赢家若仍是 FF/BF，明确报告种子胜出，不能记作 LLM 成功。生成候选中的设计最优者另作诊断，不替换正式赢家、不额外获取验证机会。

## 数据与验证隔离

固定4个设计案例、4个验证案例。每个 split 只有2条不同的历史序列，均取前128个物品，再交叉容量100/500；绝对物品大小不缩放。来源、SHA、前缀依赖和全部重合审计见 DATA_PROVENANCE.md。设计文件不含验证值。

这些是公共、项目中曾可见的2024历史数据。验证只对本次前瞻选择过程隔离，不是私密/从未见过的数据，也不能排除预训练或既有开发暴露。缩短到128改变原任务的终局效应。容量500逐案例一致设置，保留先前更正含义。

两个臂只依据设计结果分别选最终赢家并写入不可覆盖的承诺文件，包含源哈希、图身份、设计统计和来源。此后才读取验证数据进行评分，包括全部基线验证。已发表公式的设计与验证参照也在承诺后计算。验证结果不进入提示、选择、提前停止阈值或协议修订；即使更差也不换赢家。

## 评分数量与账本

上限120次评分请求：22×4设计=88；两个固定赢家各4验证=8；FF/BF/已发表公式三参照各8=24。FF/BF 的同一设计观察同时承担种子和参照角色，只算一次。不同生成记录不缓存复用；赢家验证角色即使图相同也按预登记分别执行，不从重复中取最优。

完整账本先建立208行：22×8候选/案例行、3×8参照行、2×4赢家角色行。候选的验证行默认“未选择、不运行”；被选中的候选只链接预登记赢家验证角色，不重复派发。格式拒绝、数值失败、诊断/资源未解决、基础设施异常和预算未运行各有不同状态。缺测不是功能失败，也不能删除后重新计算分母。

## 后端、解码与预算

复用已经审查的本地 fresh-server /completion 传输：固定权重/运行包/非思考模板，单请求、无工具、无公网/付费接口、无跨请求 KV。两臂的 sampler 完全相同，实际 seed 按槽覆盖并精确核验回显。输入含全部模板 token；上下文不足停止，不删父代或截断描述。

拟定输出384 tokens，比此前接口512上限更窄；输入上限1660，使总量加4 token余量不超过2048。22个请求的绝对输出请求上限8448 tokens，输入上限36520。实际数值与EOS/截断/停止原因全部报告。JSON-schema 是否采用，以同一固定schema的单次非计分烟测及独立复核决定，必须在任何正式结果前冻结；不支持则先冻结纯文本合同，不能在正式失败后切换。

每个模型 server 保持2推理线程、1 HTTP控制线程、4GiB地址空间、采样RSS4GiB终止阈值、120秒生命周期/240CPU秒；启动前要求MemAvailable至少5GiB。评分继续使用已验收且不修改的 DAG worker：20CPU秒、30墙钟秒+1秒清理、2GiB地址空间、400000B stdout和16384B stderr。每请求还受64节点、10000向量长度、256放置和500万抽象工作量约束。

聚合预算和预留值以最终 protocol.json 为准；包含分词、完整性核验、父监督进程、server、评分与清理，分阶段报告实测及保守未知成本。每次派发预留完整限额，迟到请求不缩限运行。内核限制是每进程的；RSS采样和聚合观测/预留不冒称总进程树硬上限。

## 停止与验收

普通模型格式/非法DAG、重复、截断、输出上限或已发送后的生成超时都保留槽位，不重试。基础设施、完整性、持久化、未知清理、预算或上下文失败停止后续请求。如果在配对两次之间停止，保留已运行一侧和另一侧not_run，不能声称实际机会或计算量相等。

只有精确源/数据/提示/模板/模型/配置冻结、手写适配器测试和独立复核完成后，才申请一次正式批次授权。默认入口不得调用模型或正式评分；授权flag本身不是授权。正式结果要先独立核验全部保存输出、分配、选择轨迹、账本与成本，再作描述性结论。
