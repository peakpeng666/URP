# P4：CIFAR-10 / RL 架构选择 CPU 先导结果

## 结论

真实 CIFAR-10 监督训练、REINFORCE 奖励更新、随机搜索对照和检查点重评分均已完成。本轮主要证据是端到端链路可运行、成本与选择记录可审计；不能据此判定 RL 比随机搜索更好。

固定监督基线从未训练的 10.0% 提高到两轮训练后的 19.1% 搜索验证正确率。每轮仅使用 4,000 张训练图片，没有做独立评估或官方测试。

## 实际成本

两方法按相同候选次数、轮数、更新数和图片呈现量对照，计算量与时间并不相等。所有重复采样都重新训练，未使用缓存或继承权重。

- 真实搜索子模型：48；固定监督基线：1；正式训练失败：0；未完成尝试：0
- 子模型优化器更新总计：3,136 次；训练图片呈现总计：392,000 次，其中搜索为 384,000，基线为 8,000
- 搜索验证图片呈现：48,000；基线训练前/后验证：2,000；检查点审计额外验证：49,000；合计：99,000
- REINFORCE 控制器优化器更新：24 次；选优后额外重训：0；官方测试图片推理：0
- 固定基线子模型墙钟 / CPU：2.940 / 2.939 秒
- REINFORCE 三次搜索墙钟 / CPU：52.607 / 52.592 秒
- 随机搜索三次搜索墙钟 / CPU：50.642 / 50.619 秒
- 检查点审计墙钟 / CPU：5.573 / 5.567 秒，单列而不假装免费
- 搜索进程最高 RSS：488.6 MiB，单线程 CPU，无 GPU

训练正向卷积/线性 MAC：REINFORCE 422,967,808,000，随机搜索 378,927,616,000。这里只计卷积和线性层的正向乘累加，不含反向、优化器、池化等，不能写成总 FLOPs。逐项成本见 results/search_summary.csv。

子模型计时含构建、训练、验证和检查点保存；整次搜索还含控制器及日志。搜索进程整体启动与数据读取时间另见 artifacts/search_process_time.txt。下载、数据准备、工程单元测试不混入搜索候选预算；它们的日志/时间信息单独保存。

## 解释边界与后续

只有 8 个小 CNN、每个 2 轮、3 个配对搜索种子。这是短训练的低保真选择任务，没有验证架构排序在充分训练后是否保持；控制器只有 8 次更新/种子，也没有收敛证据。固定基线不是强 CIFAR 分类基线。控制器使用三个独立分类策略，不是递归 NAS 控制器或现代 NAS 论文的完整复现。

下一阶段应另行冻结预算与独立评估划分，对预先选定结构从头更充分训练，检查低保真排序是否稳定，并增加搜索种子和公平计算量对照；正式测试集继续保留到模型与规则完全冻结。不能把本轮搜索验证分数当作最终泛化结果。

官方数据与 API 来源、算法细节和版本边界见 PROTOCOL.md；复现命令见 README.md。数据集下载文件、虚拟环境和缓存不进入交付包。
