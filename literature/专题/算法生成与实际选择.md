# 算法生成与实际选择

研究对象是可跨实例调用的算法或组件。让模型输出一道题的路线、调整算法参数、选择库成员、运行中换算子，属于不同决策。先固定宿主、输入、输出和评价，再比较生成机制。[P026](<../笔记/01_大模型自动算法设计/逐篇笔记/P026.md>)、[P496](<../笔记/04_算法选择与动态配置/逐篇笔记/P496.md>)。

## 生成方法的共同接口

| 方法 | 表示与生成 | 执行反馈怎样使用 |
|---|---|---|
| EoH | 思想与代码配对；探索、修改、调参、简化 | 候选评分、排名选父、截断留存 |
| FunSearch | 固定骨架中的可变函数；岛模型与表现分簇 | 实例表现定义簇和质量，短程序偏好影响抽样 |
| ReEvo | 程序配对比较与长期反思 | 文本反思进入下一次提示 |
| LLaMEA-HPO | 结构与数值参数分开 | 内层调参后向结构搜索反馈 |
| GP超启发式 | 表达式树、终端特征、函数集 | 固定模拟器执行并评价规则 |

对应[P177](<../笔记/01_大模型自动算法设计/逐篇笔记/P177.md>)、[P321](<../笔记/01_大模型自动算法设计/逐篇笔记/P321.md>)、[P416](<../笔记/01_大模型自动算法设计/逐篇笔记/P416.md>)、[P252](<../笔记/01_大模型自动算法设计/逐篇笔记/P252.md>)与[P245](<../笔记/04_算法选择与动态配置/逐篇笔记/P245.md>)。GP与LLM的对照应共用观察、动作接口和评测器；函数集、树深、控制流会改变表示空间，需要一起记明。

生成器负责提出程序；宿主维护搜索状态，独立checker验收输出。所改组件可以是候选评分、插入优先级、移除规则或受限调度。目标函数、实例、检查器和资源计时保持固定。

## 库内潜力与部署收益

记L为算法库，x为实例，c(h,x)为固定求解预算下算法h的期望成本，越小越好。

```text
SBS：在训练数据上选定并冻结的单算法 hₛ。
VBS(x)：min_{h∈L} c(h,x)，用于事后诊断库内潜力。
实际策略：先计算允许特征/探测，再执行 π(x)。
选择差距：E[c(π(x),x) − VBS(x)]。
```

SBS并非任意选择器损失的数学上界；一个误选的选择器完全可能比SBS差。随机求解器的c由独立重复估计，直接在带噪单次运行中取最小值会乐观偏置。[P070](<../笔记/04_算法选择与动态配置/逐篇笔记/P070.md>)、[P093](<../笔记/02_算法库生成与推荐/逐篇笔记/P093.md>)。

实际策略的预算B同时覆盖特征、probe、选择、求解、检查和回退。并行运行所有成员再取优是一种可部署组合，但应支付所有成员资源；免费VBS只是诊断参考。

新增成员h的价值用同一留出任务、总预算和回退规则下的配对差衡量：

```text
Δ实际 = E[J(π旧,L;x,B) − J(π新,L∪{h};x,B)]
Δ潜力 = E[VBS_L(x) − VBS_{L∪{h}}(x)]
```

先比较有效计划率，再比较质量与费用。两种Δ可能不同号；这能揭示候选缺乏作用、选择器没识别专长，或新增特征费用过高。Hydra、DASH、EoH-S和P142分别提供相关先例。[P244](<../笔记/02_算法库生成与推荐/逐篇笔记/P244.md>)、[P430](<../笔记/01_大模型自动算法设计/逐篇笔记/P430.md>)、[P168](<../笔记/02_算法库生成与推荐/逐篇笔记/P168.md>)、[P142](<../笔记/02_算法库生成与推荐/逐篇笔记/P142.md>)。

## 推荐失败怎样转为动作

| 观测与检查 | 能支持的判断 | 可比较的动作 |
|---|---|---|
| 同预算下另一个库成员成功 | 存在可利用的选择差距 | 重新选择、改特征或补probe |
| 调参后同算法改善 | 配置不足可能贡献了失败 | 经典配置与生成新结构 |
| 独立checker发现违例 | 当前输出或接口不满足规格 | 修复、拒绝、回退 |
| 当前全库都失败 | 在已测算法和预算下未得到有效结果 | 增加预算、修补组件、扩库 |

全库有限预算失败仍不能单独判定原问题不可行。原因解释的价值体现在选择干预后的净收益，文字解释可作为候选假设。
