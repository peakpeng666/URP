# P184 Evolving Instance Specific Algorithm Configuration

文献：Evolving Instance Specific Algorithm Configuration (Malitsky et al 2013)

原文：[Evolving Instance Specific Algorithm Configuration (Malitsky et al 2013)](<../../../../papers/Evolving Instance Specific Algorithm Configuration (Malitsky et al 2013).pdf>)

## 来源与结论

Malitsky、Mehta、O’Sullivan，SoCS 2013，PDF1有 Proceedings of the Sixth International Symposium on Combinatorial Search 与 AAAI 2013版权；9页，对应印刷132–140页。逐页1–9原文完整材料，包括第9页所有参考文献；原图核2–8（伪代码、流程、公式及全部表）。

EISAC 已有跨实例在线更新和有限评测补充的机制：按特征重新聚类，聚类变动足够大时重选簇内 solver，EISAC+ 用乐观估计避免评完矩阵。但库内未知标签估计是经验启发式，不是可信下界；论文实验主要验证固定库上的新实例流，新增 solver/特征及多核 κ>1 在结论仍列待扩展。人工排序的漂移流中明显获益，打乱且初始样本代表充分时反而更差。完整 CPU/墙钟费用未核算，不能把少矩阵单元等价于总成本下降。

## 1 问题、状态与路由

基本 ISAC：训练特征缩放到[-1,1]，g-means 分簇，剔除过小簇后把点送至最近簇，每簇调参数或选 solver；上线把新实例特征送到最近簇，执行已绑定配置（PDF2）。把多 solver 看成单个算法的一个类别参数是表述统一，不是在执行中改变同一求解过程。EISAC 动态发生在连续实例之间，不属于单次 solver 内的 DAC。

框架用 I_t/F_t/S_t/C_t 表示已知实例、特征集合、solver 库与聚类。初始阶段有训练实例的全库性能；到达新实例后先用当前映射求解，再吸收实例/反馈，以免把本例结果提前用于本例推荐。若有 κ 个核，每簇允许 κ 个并行 solver；实验实际 κ=1，结尾将多 solver 验证列未来工作（PDF3、8）。

每隔 δ 个实例重算聚类，比较同一当前实例集合的两套分区。Adjusted Rand Index（ARI）按点对同簇/异簇一致性扣掉随机一致，低于 λ 才接受新分区并更新绑定。它衡量几何分区稳定性，不直接衡量选择 regret、性能漂移或模型规格正确。即使特征分布不变而性能发生变化，也不能从 ARI 高推出无需更新。反过来，重新分区并不保证改善选择。这是推断，不是本文定理。

实验窗口每吸收 δ 个新例同时删除最老 δ 个，保持初始200/500例规模；δ=1 是主结果，10/50/100“趋势相似”仅文字报告。簇最小50或100，λ=.5/.95 均人为给定，不是无超参数系统。

## 2 簇内组合目标与欠评测

PDF4式1–4：y_j 表示选 solver j，x_ij 表示训练例 i 由 j 负责，约束每例一个 x、x⇒y、Σy=κ，最小化 ΣT_ij x_ij。已知完整时间矩阵时是选择 κ 个成员、每训练例取成员中最快的组合目标。κ>1 与并行同跑首完成时间对应，但并行 CPU 使用、线程竞争、暂停/重启开销不在这个目标内。κ=1 回到每簇平均性能最佳。

新增 solver 的设计：各簇抽 (|I_0|/|I_t|)|C| 样本试跑，若样本上加入该 solver 改善总运行时间，再补完整簇；否则跳过其余例（PDF4–5）。样本挑法、误拒率、置信区间和独立新增 solver 实验都未给。本文支持“已有少量试跑接入方案”，不能支持已验证零样本接入、可靠辨认新专家或新代码合法性。若实际窗口一直保持 |I_t|=|I_0|，该比例本身不产生小样本折扣，进一步说明新增 solver 设计不能直接套成本表。

EISAC+ 的懒更新（PDF5 Algorithm2）：
1. 对已测完全部 solver 的实例 A_t，按 runtime 排名，求 e_p=平均(T_best/T_pth)，一般≤1
2. 新例仅知道已运行集合 S_t^i；把这些已知 solver 假设为全库最差的若干，已知最快 b 对应排名 p=|S_t|−|S_t^i|+1
3. 所有未测 solver 暂赋同一估计 e_p T_ib，求新的最优簇组合 NC
4. 若 NC 与旧 BC 相同，停止；否则实际评估 NC 中未观测单元、更新并重复

这是一种启发式“乐观补全再验证”。历史平均比例不是每个新例的数学性能下界，更不是概率置信下界，因此“最优集合没变”不能证明遗漏算法不可能更好。它也未利用算法身份为未观测成员给不同估计。未执行单元属于缺测，没有运行时间下界；跑到上限未完成才属于删失，本文 PAR10 直接赋惩罚而未显式拟合删失分布。

原图核定伪代码疑点：Algorithm2第4行仅为 p<|S_t| 定义 e_p，而 κ=1 时第7行会得到 p=|S_t|，终端排名的系数缺定义；初始化 BC、完全观测集合为空以及零时间分母也未完整写出。仅记录伪代码，不据此宣称实际实现或历史实验必错。本主题没有 EISAC 匹配源码。

## 3 实验、成本与分母

SAT 使用 SATzilla 2011 数据：31 solver、1200秒截断，原3000余实例，删除全库都超时的实例后2524例；52个不含 local-search probing 的标准特征。初始200/500例全矩阵训练，其余2324/2024作为顺序到达流。BS 按初始训练选择；VBS逐测试例事后最快。SAT的VBS解出100%是过滤决定，不能证明库无缺口。

三种流：随机打乱；Industrial→Crafted→Random；按全库平均 runtime 从易到难排序。第三种用全反事实构造压力序列，属于离线实验设计，不能说部署可在无试跑时知道实例难度。静态与进化方法按同一流比较有价值，但不是实际时间漂移数据或新约束测试。随机顺序、g-means、solver运行没有给足重复种子/置信区间；“significant”多为描述性词，不能补造统计检验。

MaxSAT 2012 四类别（MS/PMS/WMS/PWMS）共2681例、14 solver、2100秒；SAT基础特征加5个软子句权重统计。某 solver 根本无法读取另一类别的输入，也统一记作 timeout（PDF7）。这混合了能力/接口不兼容与慢运行，是 R1 的关键反例：同一惩罚标签不能诊断原因。MaxSAT 保留部分全库未解例，VBS约89%–94%，分母不同于过滤后的 SAT。

论文只报 #Train 和 %Eval，结论承认离线努力度量粗糙（PDF8）；有的激活只聚类，有的重选1–2簇。50秒×1000例训练可72 CPU天是引用先前研究说明潜在成本，并非本实验全账。EISAC+少评单元不等少同等比例CPU，更不等真实端到端两倍加速：省掉的评测时长、聚类/MIP/特征、在线首运行与补跑是否复用、失败/超时都需分账。

## 4 正反结果

PDF6 Table1：有序 SAT，初始500、c50、λ=.95 时 EISAC解1606/2024，静态ISAC795；PAR10 2556对7334。但触发611次，对 λ=.5的1261例/4次触发不能说既最大性能又只训四次。相同设置 shuffled 时 ISAC1548、EISAC1539，后者仍触发674次，性能无收益。

PDF6 Table2：初始200有序流，EISAC+评59.5%的单元，解1671对完整EISAC1725，PAR10 3440对3160；有节省也有质量代价。500例的83.8%评测下1264对1261近似持平，不能统一说“半成本同样效果”。PDF7 Table3 易→难初始500、λ=.5：EISAC+1400还低于BS1410，完整EISAC1485。

最强负结果在PDF8的主 MaxSAT表（顶部标Table4，下方又重复Table5标题，正文称Table5，引用须保留这个排版歧义）：
- shuffled、200训练：ISAC1802/2481；EISAC1540/1544；EISAC+1502/1479。ISAC PAR10 5675，EISAC+7949/8132；后者还激活872/1259次
- shuffled、500训练：ISAC1724，EISAC1564/1555，EISAC+1474/1475，普通静态近邻更强
- category ordered、200、λ=.95：EISAC1958对ISAC1087支持漂移下适应；EISAC+1796、48.9%评测，是便宜但明显少解162例的折中

因此结论应为“人工分布变化时有条件改善，稳定代表性训练时可能付出高更新成本并显著退化”，不能从近翻倍正例概括普遍进化有益。结尾关于新增/删除特征“只会改善”、新 solver 不改变趋势是作者未来推测，未被展示实验支持。

## 5 研究问题与农业边界

R1：分区变化触发重选/补测已有先例，但仅看特征变化或失败惩罚无法区分误选、库缺、输入格式、建模错误；SAT全库失败过滤更不支持缺口诊断。

R2：联合聚类、配置专家和实际路由是经典机制；本篇主要演化选择映射而不是生成新代码，最近邻应与P258、SATzilla筛库及DASH真实路由分层比较。

R3：新实例流已有真序贯预测→更新，新增 solver 少量试跑只有设计；新特征/新约束/κ>1不能写为全面已测。新农业约束改变问题/输入时，应先核 solver兼容和可行性，不把读取失败等同超时。

R4：懒补单元是有价值的成本意识先例，但更好的预算分配要保留实际可见标签、删失区别、误拒概率和全账。未来可在已有合法VRP/覆盖solver上研究，而非先承诺本模块证明有效。
