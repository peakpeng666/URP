# P429 弱性能测试可掩盖优化，但非显著与失败必须分开

原文：[Rethinking Code Performance Benchmarks for LLMs (Le et al 2026)](<../../../../papers/Rethinking Code Performance Benchmarks for LLMs (Le et al 2026).pdf>)

arXiv2607.07619v1（2026-07-08），38页全部读，30–38参考文献；关键伪码、流程、提示词及横置表5已原图核对。

## 问题、数据和推断单位
重评4个Python函数级性能基准共1538任务：EffiBench1000、Enamel164、EvalPerf118、Mercury256。每任务canonical基线与benchmark-provided performant实现比较；所谓performant不是已证明更快真值，来源有GPT3.5、历史LeetCode和人工优化混合（页5–8）。每程序原测试套件运行30次，i5-8500单机同条件一次一任务、300s单运行超时，T0的DeepSeekV3.1/GPT4o-2024-08-06判断/生成（页9–10）。重复计时是同一任务的噪声测量，不是30独立任务；同环境反复跑不自动排除缓存/时间序列依赖。30是选定经验数量，非普遍统计功效保证。
每任务单侧Mann–WhitneyU比较更快，再Cliffδ；跨任务均值配对单侧Wilcoxon。论文只说非参数适用，仍需独立样本及Wilcoxon差值对称等条件；MWU不在任意异形分布下简单等同均值/中位数差。δ是排序优势量，large不代表实际秒数/百分比足够有价值。阈值写δ而非|δ|，应说明方向。1538个逐任务检验及后续多模型/套件未见多重校正。先筛p<.05任务再说子集整体p<.001（页11）是选择条件下总结，不是独立确认。

## 核心发现与特别重要的分类问题
表2：94/1538=6.11%判显著更快，其中92large、1medium、1small；1444=93.89%归non-significant。但页9明确功能不通过或任一运行超时都直接计为non-significant，故不能说1444均具有有效p≥.05，也不能说统计不可区分/等效/没有实际收益。应写“未获得作者定义的显著更快判定”，单独索要错误/超时率。
对1444中分层抽308人工标注：84无性能影响类、15完全相同、209潜在性能变化；2作者最终κ.93，1200人时（作者报告），不是客观性能证明。LLM在同308与人工κ.72/.75后扩展1136，判潜在性能变化864/840；一致性不是分类真值或未来错误率。页14把builtin替换/循环改写因复杂度不变就判“无性能影响”过强，常数开销/解释器实现可变；页24自己又承认常数因子重要。不能把209分类为已证明加速。

## 测试生成闭环
输入problem description+canonical代码，不给优化版。生成agent分2批各5 deterministic测试（128Kcontext约束）；在canonical执行；失败交诊断agent抽error/rootcause/line；repairagent改预期值/输入/大小但不改被测代码；每批最多3轮，合并10测试再最多5轮验证，最终仍失败则删除（页17–19，图1/2）。此反馈主要功能/异常，不是按实时p值追逐速度；页25提出“迭代至显著”的设想是未来工作，不可归为已实现。输入/预期值依赖canonical修复，canonical本身可能有误，无法证明真实规格正确；删除失败会改变覆盖，需保留诊断与失败数量。停止后可能少于10例或空集，处理细节未报告。
RQ3只测209人工潜在变化+1136剩余=1345，排除了人工99无意义变化。新套件DeepSeek323/1345=24.01%，GPT4o342/1345=25.43%判显著更快；COFFE27/1345=2.00%、6/1345=.45%。人工子集94/209、102/209，剩余229/1136、240/1136；全部新增判定δlarge。不能对1538不加说明套用24–25%，也未报告多agent与COFFE总API/修复/执行等预算配平。
成功例（页20）longestsubstring原最大长度10，新测试'ab'*500000和'a'*1000000均为百万字符；正文称长度500000与片段不一致，但重点是扩容。两个滑动窗口都线性，indexjump与逐字符shrink可有常数收益，反证仅看渐近阶不足。失败例（页21）生成测试错调用canonical内部binomial_Coeff而非公共sum_Of_product，优化版移除了helper，导致接口不兼容而非优化错误。

## 新模型评测与范围
RQ4三生成模型各1538任务，原显著数GPT4omini96、ClaudeSonnet4.5 150、Gemini2.5Flash80；DeepSeek测试396/680/274；GPT4o测试402/698/262（表5页22及23）。不是每任务speedup22.19%。正文22.19%称额外可区分比例，24页32.66%另汇总口径不充分，不硬重算成原结论。Claude更好被猜为更长推理，未因果消融。生成模型具体提示/生成次数/费用未完整呈现。
局限明确Python函数级、执行时间；不包括内存、能耗、I/O、并发、repo交互。生成压力输入是否仍在原规格范围、是否代表农业部署分布还需独立审查。大输入能显差不代表实际使用加速同量。

## 项目映射
R1低分/无显差不能直接判库缺口，先检查失败、checker与输入压力是否合理；诊断agent的文字不是真因证明。R2可用压力测试揭示算法互补，但公共接口、约束有效性和真实输入分布必须保持。R4比较需完整费用、硬件/缓存/批次设计及失败分类，不照搬30runs和p.05即严谨。新测试生成也属于基准设计/模型选择，冻结后在独立保留任务族测最终收益；不要运行直到显著而仍用普通p值。
