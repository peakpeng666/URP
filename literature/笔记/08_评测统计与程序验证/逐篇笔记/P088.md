# P088 Performance profile的相对基准与成功定义

文献：Benchmarking Optimization Software with Performance Profiles (Dolan & More 2002)

原文：[Benchmarking Optimization Software with Performance Profiles (Dolan & More 2002)](<../../../../papers/Benchmarking Optimization Software with Performance Profiles (Dolan & More 2002).pdf>)

13页全文含证明/参考文献已读；原页1、3–12视觉复核。版本：目录2002，提供的实际上是arXiv:cs/0102001v2（2004-03-05）作者稿，不把二者计独立研究。

## 定义与关键纠偏
固定问题集P与求解器集S，tₚₛ是s解p的时间（也可换函数调用等可比资源），rₚₛ=tₚₛ/min_{s′∈S}tₚₛ′；profile ρₛ(τ)=|{p:rₚₛ≤τ}|/|P|（页3）。这是相对同一实例上“本组被测算法的最佳时间”，不是问题目标函数的真最优值。profile数学定义不要求真最优已知；要求已有可比较成功/达标事件，若该事件定义为达到真最优而真最优未知，才是事件不可操作，不是profile本身禁止使用。

失败比值设专门大常数r_M，高于一切成功比值；ρₛ(1)是并列计入的最快比例，ρₛ(r_M−)才是成功率，ρₛ(r_M)=1本身无实际成功含义（页3–4）。本文页10用ρₛ(r_M)叙述成功比例应按页4定义理解为左极限/平台，不照抄为精确点值。失败不被删掉，免去“只保留所有求解器均成功”对稳健方法的惩罚。全算法都失败的实例如何定义时间分母没有详述，实际应用应先约定失败哨兵与分母处理。

性能曲线交叉说明不同容许倍率下赢家不同；一条曲线全域占优仅是经验分布一阶占优，不意味着每个实例都更快（页9–10）。ρ是测试集经验比例，不自动成为未来任务概率、统计置信区间或真实选择器成绩。其分母类似事后VBS时间，只作归一化基准，不提供知道最优算法的上线oracle。增加/删去S中的算法会改变分母，跨不同参照集不宜直接比较曲线。

## 理论与实验
单个问题记录变更最多改变每个profile 1/|P|；若每个比值误差≤ε，则两经验CDF的L1面积差≤ε（页4–5定理2.1）。证明排序两个比值序列，分段逐一增加，差面积每项至多ε/|P|，归纳完成。它是比值扰动条件下稳定性，并非对任意计时噪声或微小分母的无条件保证；单点CDF台阶附近仍可跳变。

COPS2.0共17应用×4参数实例（68），控制/参数估计子集11应用×4（44）；LANCELOT、MINOS、SNOPT、LOQO。SparcULTRA2/Solaris7，同问题依次跑求解器，3600s wall-clock杀进程判失败；记录AMPL模型解释/导数系统时间+solver时间，若与wall-clock差>10%重测，验证报告可在10%内重现（页5–6）。未统一停止标准，认为影响通常不超2倍但不是证明；内存不计；两算法一阶两算法二阶，导数成本/适用条件不同。

子集LOQO赢约61%，但若要求>90%成功则SNOPT更突出；全COPS上LOQO经验曲线支配，约58%最快、87%成功（页7–11图4.1–5.1）。差异与自由度、二阶信息有关，属于作者解释及描述证据，不是随机因果试验。线性规划七solver版本例展示外部数据应用（页11–12图6.1），仍受Mittelmann选定问题集限制。本文自己明确未解决如何选有代表性的测试集（页12）。

## 对主线的意义
R1：失败必须保留，因超时或停止判据失败不等于算法库不存在更好解，更不证明建模正确。R2：profile可描述每个实际选择器/算法的端到端时间比，不能把归一化用的事后最优当实际推荐效果；互补曲线不能识别“应给哪个实例选谁”。R4：指标若用时间应把所声明流程的输入处理、特征、选择、测试等费用合计；调用次数与时间不能混为同一预算。

农业/VRP需要先定义容量/时窗/覆盖/运动约束与可行达标事件。若只有最好已知值，可按明确阈值测time-to-target，不标“最优证明”；非法解需独立失败标签。可结合P528随机运行达标时间CDF，但本篇横轴是相对各实例最佳时间、纵轴跨实例，不是固定实例多次随机运行的时间分布。最近邻P479排序损失幅度信息而profile保留倍率；统计推断仍另做。未核本篇perf.pl仓库实现
