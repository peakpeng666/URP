## 核心问题与方法
固定 M 个任务，各算法在每个任务上有 N 次训练运行和归一化分数。作者分析少量运行时的点估计、偏差、区间和评价协议。游戏是任务层单位，训练 run 是任务内随机单位，训练后多回合评估又是一层；固定 seed 不保证相同运行。附录 Fig A.13（p18）同 seed 的两组各100次 DER 运行相关性低，涉及 GPU 非确定性，不能把“用了相同 seed”自动当作理想配对设计。

主要工具（§3–4, pp4–8）：
1. 按任务分层 bootstrap，任务集合固定，在每个任务内部重采样运行，给聚合统计量置信区间
2. 运行分数性能曲线：对每个阈值 τ，统计所有任务及运行分数超过阈值的比例；相当于各任务尾分布的等权混合，单个异常运行影响不超过 1/(MN)。它不同于先算每任务平均再画曲线
3. IQM：所有归一化 task-run 分数中间50%的均值，折中均值易受极值影响与中位数高方差。并非对任意分布都最优；p19 明确轻尾正态时均值可更有效
4. optimality gap：低于选定“期望目标”γ 的平均缺口。本文常用 γ=1 人类基准分，**不是已知真最优解差距**；应明确目标定义，也可对多个γ画曲线
5. 平均改进概率：先逐任务估计 P(X_m>Y_m)，再对任务平均。p25 Eq A.2 为所有 N×K 跨算法运行对的 Mann–Whitney U，平局计0.5，区别于只对应比较同索引运行的 win-rate。概率不反映收益幅度，1%改善与100%改善可能概率相同

## 实验与实际成本
Atari100k：26游戏，DER/OTR/CURL/DrQ/SPR及 DrQ(ε) 变体共6配置，每游戏100 run。15,600次训练，额外 DER 100 run/游戏增加2600，共18,200；每次 Tesla P100 约3–5h，总量作者估2400–3600 GPU-days（p19）。评估每run取100回合平均；重复子采样100,000组估计少量run统计性质。此计算量是论文建立证据的训练成本，不是 rliable 后处理成本。

聚合 bootstrap 默认50,000次，曲线逐点区间和改进概率2000次；部分排名200,000次（pp22,28）。重采样数不是独立训练或独立问题数，增加它只降低 bootstrap 数值误差。

Atari200M：55游戏，sticky actions，大多数5 run，M-IQN3、DreamerV2 11 run。Dopamine Rainbow 不含原Rainbow的double/dueling/noisy components，原Rainbow论文单run且无sticky actions，不能不加限定混为同一baseline（p8）。DM Control主文6任务，在100k/500k步比较；个别方法只给汇总，使用 studentized 区间而不是所有方法都有原始run（p9）。Procgen16任务，多数10 run easy mode（p10）；归一化选择会改变聚合和排名。

## 结果、反证和解释边界
- 小N下“各任务均值的中位数”有明显偏差且CI宽。SPR的5与100 run估计移动相对于声称增益不可忽略；IQM通常CI更窄，不能因此认为所有差异都显著（Figs3/4/A.15/A.17）
- 协议中引入 max 会产生额外正偏。CURL采用训练中10次评估的最大值，SUNRISE逐游戏8组超参、每组3 run取最好；对DER施加相似规则即可解释大量表面进步（pp5–6,20–21）。这支持统一选择预算与独立最终测试，而非声称这些算法在所有公平协议下完全相同
- “部署确实选N次中的最佳”是合理新算法 A^N，但一次best-of-N仍只是这个新算法的一次随机实现，需要多次独立外层重复；并且评估/选择 N 次费用都应记入（pp20–21）
- Mean受到极高游戏分数牵引：DreamerV2/M-IQN在JamesBond>50倍人类分；median、IQM、gap排名不同（p8 Fig9）。不能抽选对自己有利的聚合量再报总冠军
- Procgen UCB-DrAC相对PLR改进概率仅约40–50%，许多声称改善仅50–70%（p10）。这不是未来任意任务的总体概率定理
- 附录覆盖率实验以 DER 200 run估计“真值”；少至3 run的区间明显欠覆盖；约10 run聚合百分位区间较可靠，单游戏均值即使30 run仍可能不足（p21）。200 run参考本身有限，因此不能把近95%看作普遍保证
- CI重叠并不推出无差异，应直接对差值估CI；统计不显著也不证明零改善（p19）

## 统计独立性、测试隔离与隐藏限定
主要CI条件于这组固定游戏和已定超参，p20明确其研究调参阶段之后性能，不含超参选择变异。若研究农业新地块的推广，需把地块/实例族作为抽样单位；附录p22的跨任务与run重采样回答不同的任务总体问题，Fig A.22区间更大，不能用固定任务CI冒充OOD证据。

运行得分曲线采用逐点95%区间，不能自动解释为整条曲线、所有算法、所有阈值同时覆盖95%。本文未替项目解决多重比较、反复开发看榜或固定基准过拟合。复用评估选checkpoint/超参造成的正偏由该论文直接示范，但其统计库本身也不是防泄漏制度。

最强反证/条件：IQM会裁掉最差25%运行，农业中的不可行、碰撞或误作业不能被裁掉后只报稳健平均；应单列硬约束违规率、失败/超时以及最坏尾部。平均改进概率不反映成本或效应幅度，优化gap目标也非真正最优。报告多个预先规定且业务有意义的量，不追逐最利于自己的指标。

## 原文公式与文字核查
- p7 Eq1后将总体尾分布写成 1/N Σ_m F_m，而定义有 M 个任务；应为 1/M。原PDF核见，非抽取错误
- p22将覆盖写作 α×100%，基本bootstrap与percentile式的端点/α索引明显与常用置信区间表达不一致，原图确认。不要照抄此式实现；本文代码未在包内，不据此推定代码有同样错误
- p25把上置信界高于0.75作为“meaningful”条件引自P030；上界超过阈值不能证明真实改进概率大于0.75。若项目需要此结论，应要求相应下界越过阈值（读者统计解释，不冒称原文结果）

## 项目应用
失败诊断：低置信或多次运行不稳定首先是测量不充分，不能据此诊断算法库缺口；先定位实例/运行层误差，检查可行性与目标定义，再谈库补全。本文没有实现该在线诊断器。

算法库与选择：评价算法库/selector应在相同任务与独立测试上给任务层或层次不确定性，实际selector得分不能用VBS代替。需要报告失败尾部与路由代价，公平控制调参和生成选择预算。本文不生成库、不训练selector，没有互补性联合优化成功证据。

预算与评价：best-of-N、反复调参、候选筛选均为算法的一部分；计入所有运行、特征与验证开销，独立重复整个生成/选择过程。建议的统计后处理不等同于cheap proxy，未证明可减少LLM调用且保持可靠排序。

近邻：与P030互补，P030强调调参/数据变异，本文更强调调参后少run的跨任务估计、协议max偏差及稳健聚合；二者都不能直接给农业样本量规定“至少5/10/29”统一答案。
