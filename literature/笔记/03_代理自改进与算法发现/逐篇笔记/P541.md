## 一句话结论与版本
所供 arXiv:2305.16291v2，2023-10-19，42页；目录说明 TMLR 版未取得，本次不将它算已读。Voyager 是真实的“情境任务→检索技能→生成复合程序→执行反馈→自评入库”系统先例，不应把技能库复用抹成纯文本记忆；但它在 Mineflayer 高层接口和简化死亡机制下优化探索能力，并未验证农业运动安全或真正的算法库缺口诊断。

## 对象、机制和假设
1. 自动课程不是学习器参数更新：GPT-4 依据库存、场景、已完成/失败任务提出下个可达又新颖任务。所谓 in-context novelty search 是解释性类比，没有显式新颖性目标函数或最优化保证。提示有手工约束和 warm-up：5个任务开放附近实体，7个开放完整库存，10个开放 biome，15个开放健康/饥饿/时间/额外问答（PDF20–23、表A.1）。提示明确禁止需屏幕验证的建筑、种植、交易等任务。
2. 技能为可执行 JavaScript 程序，描述由 GPT-3.5 生成并嵌入；任务建议加环境反馈形成 query，取 top-5 程序给 GPT-4 组合，成功后把新代码加入库（PDF3–5、图4）。检索是实际链路，但相关技能命中不等于算法实例上最优性能推荐；最终动作还要经过生成器。
3. 三种反馈分开：底层 API chat 的缺资源等环境反馈、解释器错误、另一 GPT-4 根据状态给出的任务成功与 critique。单任务至多4轮生成，不成功即把失败记给课程、换任务（PDF5–6、19伪码）。这既能定向修补，也可能把难题暂时绕开；失败信号未分解成“库缺能力/检索错/组合错/环境不可行”。
4. 无模型微调不等于零训练知识或零工程：GPT-4 预训练、GPT-3.5、embedding API、Mineflayer 路径/采集/战斗控制原语均是依赖。研究明确不与像素输入/键鼠输出策略直接比较（PDF6–7）。

## 实验、分母与预算
主设置 GPT-4-0314、GPT-3.5-0301、ada-002，课程temperature .1，其余0。探索每方法3次、160次提示生成迭代。正文报告平均63类物品，约AutoGPT的3.3倍；地图距离2.3倍。附录PDF41交代轨迹仅在 GPT-4 交互时采样，图7是轨迹最小包围圆，不是连续完整覆盖率或作业面积。
表1：木/石/铁工具为6±2、11±2、21±7轮；AutoGPT为92±72、94±72、135±103，15.3倍来自木工具提示迭代，不是端到端墙钟。钻石只有1/3成功（102轮），不能称稳定掌握。去技能库的石工具9±4比完整系统11±2更快，前期简单技能不是处处收益。
表2的新世界、新任务评估把库存清空，每任务3次、最多50轮；完整Voyager四项均3/3，钻石镐19±3轮，去技能库36轮且2/3。AutoGPT加入同一技能库后部分从0/3升到1/3或2/3，说明库确有跨代理可复用贡献；但基线重实现，AutoGPT把无执行错误当子任务成功、缺自验证，不能归因于单个组件的纯公平优越。新任务“zero-shot”允许测试时多轮执行、修补、任务分解，非一次调用零反馈。
表A.4检索309样本，top-1 80.2±3.0、top-5 96.5±.3；标签构造、独立分割细节不足，不能把96.5%写成成功率或性能选择准确率。GPT-4两个版本曲线相近只证明所测0314/0613，不是任意模型鲁棒性。
消融图9：随机课程减少93%物品、自验证去除减少73%、生成GPT-3.5获得物品约少5.7倍。随机课程从Voyager发现的101物品采样，手工课程是定向钻石十步；课程与指标适配会影响比较。仅3次运行，未给各差异的显著性检验，阴影不可自动解释为统一置信区间。
调用代价未完整折算：160次code iteration不等于160次总LLM调用；课程问答、自评、描述和embedding、失败执行也要计入。PDF10只给GPT-4当时较GPT-3.5贵15倍，无完整每任务美元/时延表，不能断言总体省钱。

## 附录逐段核读与反证
PDF11–18含结论/影响/全部参考；19–31为算法、prompt、原语；32–34为5段技能代码；35–37为critic prompt；38–42为设置、对照、逐run物品/地形、补充检索和版本图。
最强限制不是“没有执行”：有实际游戏执行，但critic以最终库存作代理。PDF36–37用现有腐肉推断刚杀僵尸、饱腹值20推断成功吃东西；缺少前后差分与事件来源时，无法保证动作真的满足目标。作者PDF10承认自验证漏认蜘蛛线、不存在物品任务、假API/错误燃料。PDF38死亡后复活并保留库存、有自动回收工作台炉子，明显低于物理机器人失误代价。
原始示例还揭示成功轨迹不保证通用代码：PDF32 craftWoodenPlanks 在找不到log时调用mineWoodLog，却没有重新赋值 const logInInventory，随后indexOf(undefined)可能为-1；这是所展示程序分支的静态缺陷，非运行证明。PDF34 catchFiveFishSafely while(!waterBlock)无总重试上限，钓鱼取消时i--亦可无限重试，尽管PDF30提示禁止无限循环。说明语言约束不等于强制验证器。需要结合随包实际代码是否同版本，不能扩大成所有Voyager运行必失败。

## 项目启示与最近邻
R1：已有充足机制先例是“执行错误/缺资源→修补→失败记忆→换任务”，待研究的是可靠诊断信号及其代价。R2：库积累、检索、生成组合确有闭环，但未把选择器的性能损失共同优化，不能当 selection-aware portfolio 的完备实证。R3：新任务通过描述检索和代码组合低参数接入得到有限正证；新工具/新约束仍要正确接口、状态与验证器，不能零成本认证。R6：无需Jev。
农业对应应是任务/实例描述→候选求解器或动作模块→独立可行性与代价验证→保留/回退。Mineflayer移动成功不能代替田间地头转弯、作业幅宽、负载/电量/土壤约束验证；库存分数也不能代替VRP目标。与SayCan的预训练affordance选择、SayPlan的场景图/模拟器验证应区分。用户实验、复现均0。
