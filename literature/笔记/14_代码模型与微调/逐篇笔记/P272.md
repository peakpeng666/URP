## 问题与贡献：究竟放大了什么

论文针对的痛点是：一个预训练模型可以通用，但如果每换一种任务都要准备大量标注、再微调一次，使用门槛仍然很高。作者考察另一种适配方式：把任务说明和示例直接放入文本上下文，让语言模型继续生成。

这条路线并非本文首次提出。本文的主要贡献是把规模推到 175B，并用 8 个主模型、零/单/少样本三种设置以及大量不同任务系统观察它的效果和失败情形。8 个主模型约为 125M、350M、760M、1.3B、2.7B、6.7B、13B、175B；每个都训练 300B token。图 3.1 另加入 6 个更小的模型，不能把图里所有曲线都当作完整下游评估对象。（PDF 3–10，§1–3）

图 1.3 把 42 个以准确率计的结果汇总，用于展示总体趋势。作者自己说明它不是严谨的统一基准：任务难度、样本量、指标意义和重叠关系不同。应优先看逐任务表、正式 SuperGLUE 汇总及失败任务。

## 从 P067 接过来：预训练与上下文学习改变的东西不同

把一段文本分词成 \(z_1,\ldots,z_T\)，自回归语言模型使用：

\[
p_\theta(z_{1:T})=\prod_{t=1}^{T}p_\theta(z_t\mid z_{<t}).
\]

预训练的基本目标可写成：

\[
\mathcal L(\theta)=-\sum_t\log p_\theta(z_t\mid z_{<t}).
\]

这里是对论文训练方式的教学形式化。训练通过反向传播改变参数 \(\theta\)。[预测未来 token 的因果掩码、防止看见答案的意义，可结合 P067 Transformer 笔记](<P067.md>)理解。

现在把任务说明 \(I\)、示例 \((x_i,y_i)\)、待答问题 \(x_*\) 拼成：

\[
c=I\oplus(x_1,y_1)\oplus\cdots\oplus(x_K,y_K)\oplus x_*.
\]

答案按照 \(p_\theta(y_*\mid c)\) 生成或评分。此时参数 \(\theta\) 不变，变化的是输入和由它产生的中间表示。不能把“模型读过几个示例”记作“模型微调过几步”。

| 设置 | 当前输入中有多少演示 | 任务阶段是否更新权重 | 本文是否评估 |
| --- | ---: | --- | --- |
| Zero-shot | 0；可有任务说明和待处理文本 | 否 | 是 |
| One-shot | 1 | 否 | 是 |
| Few-shot | \(K\)；通常为能装入上下文的若干到数十个，部分任务 100 个 | 否 | 是 |
| Fine-tuning | 训练数据分批用于优化，不等同于同一条上下文 | 是 | GPT-3 本文未做；对照方法可能做过 |

三个容易混淆的点：

- **Zero-shot 不是零预训练数据。** GPT-3 此前已经用过海量文本；这里只说当前评测提示中没有任务演示。
- **Meta-learning 在本文首先是结构性描述。** 外循环为预训练、内循环为前向计算中的适配；它并未证明内部执行了梯度下降或从零学出了一个新算法。作者明确保留“学新任务”和“识别已有任务”的歧义。（PDF 4 脚注 1、34、40）
- **Few-shot 不保证优于 one-shot 或 zero-shot。** 例如 LAMBADA 的 one-shot 低于 zero-shot；ARC 的 few-shot 也没有稳定超过 one-shot。

## GPT-3 的结构：与原始 Transformer 相同在哪里、不同在哪里

GPT-3 是自回归的 GPT 式 Transformer，不是 P067 的完整编码器—解码器翻译网络。论文沿用 GPT-2 的预归一化、初始化和可逆分词，并在各层交替使用稠密注意力与局部带状稀疏注意力。（PDF 8，§2.1、表 2.1）

175B 配置为 96 层、隐藏宽度 \(d=12288\)、96 个头、每头 128 维，FFN 宽度 \(4d=49152\)，上下文窗口 2048 token。此处“稀疏注意力”描述注意力连接模式，不能据此把它说成只激活少数专家的 MoE。

作为量级核对，若每层注意力投影约 \(4d^2\)、FFN 约 \(8d^2\)，则主要矩阵参数约：

\[
12Ld^2=12\times96\times12288^2\approx173.95\text{B}.
\]

加上其他参数后，与表 D.1 的 174.6B 量级相符。这是近似计数，不是从作者源码逐项统计。

[**跨论文连接：**P137 ResNet](<../../13_进化计算与数学基础/逐篇笔记/P137.md>)提供残差支路思想；[P288 LayerNorm](<../../13_进化计算与数学基础/逐篇笔记/P288.md>)解释归一化计算；[P349 Pre-LN/Post-LN](<../../13_进化计算与数学基础/逐篇笔记/P349.md>)解释位置与梯度的关系。GPT-3 用 Pre-LN，但附录 B 仍使用 warm-up；这与“Pre-LN 在某些条件下可不用 warm-up”的实验结论并不矛盾。

复现结构时还要注意：表 2.1 的 13B 行原样写 \(d_{\rm model}=5140\)，与 \(40\times128=5120\) 不相等；1.3B 行的宽度与头数×头维度也不同。不能仅凭常见实现习惯静默改表，亦不能仅凭不相等就证明结构不可能——投影维度原则上可不同。精确实现需要额外代码证据。

表内数量合计约 499B，实际每个主模型训练 300B token。两者分别表示可采样语料规模和训练消耗量；某些数据源重复使用，另一些未遍历完。表中权重之和是 101%，且表注按样本比例定义；这些印刷值不应直接当作高精度 token 配额重建全部 epoch 数。（PDF 8–9，§2.2）

Common Crawl 来自 2016–2019 年的 41 个按月分片，过滤前约 45TB 压缩纯文本、过滤后约 570GB。总体训练文本按词数约 93% 英语、7% 其他语言；不是多语言均衡训练。（PDF 8、14）

附录 A 的清洗值得读到实现层面的描述：

1. 用 WebText、Wikipedia、书籍等作为高质量代理，原始 Common Crawl 作为另一类，训练基于分词与 HashingTF 特征的逻辑回归分类器。
2. 根据分类分数进行随机保留，原文采用 Pareto 随机量与 \(1-\text{score}\) 比较，\(\alpha=9\)。它保留部分低分文本，以免只剩参考语料的一种分布。
3. 使用 Spark MinHashLSH、10 个 hashes，在数据源内近似去重，并从 Common Crawl 中去掉与 WebText 高度重合的部分；去重使规模平均下降约 10%。
4. 另尝试去除评测集重叠，但这一步有 bug，详见 §10。

这里的“高质量”是与所选参考集合相似的操作性代理，不是被证明客观、无偏的文本质量指标。

## 训练配置与成本：把 Adam 接入真实配方

附录 B（PDF 43）给出：

- Adam：\(\beta_1=0.9,\ \beta_2=0.95,\ \epsilon=10^{-8}\)。
- 全局梯度范数裁剪阈值 1.0；weight decay 0.1，引用了解耦权重衰减工作。
- 最大模型峰值学习率 \(6\times10^{-5}\)，最大批量 3.2M **token**，不是 320 万条文本。
- 前 375M token 线性学习率预热；之后采用余弦下降，到 260B token 时降至原学习率 10%，剩余阶段维持该水平。
- 批量从 32K token 起，按模型大小在前 4–12B token 内逐步增至目标值。
- 在一个 epoch 内不放回采样；短文档拼接到 2048 token 序列，以文本结束标记分隔。除了通常的因果限制，文档之间没有额外的特殊注意力屏障。
- 使用 V100，并沿层间和矩阵运算内部做模型并行。论文没有在这里给出可直接据以重建完整集群运行的全部配置。

[与 P031 Adam](<../../13_进化计算与数学基础/逐篇笔记/P031.md>)对照可见，\(\beta_2=0.999\) 不是不可改变的定律；GPT-3 选了 0.95。不能把学习率、裁剪、批量和权重衰减都省略后，声称复现了原训练。

附录 D 忽略注意力运算等成本，用每参数每 token 约 6 次 FLOP 估计训练量：

\[
C\approx6ND
=6\times174.6\times10^9\times300\times10^9
=3.1428\times10^{23}\text{ FLOPs}.
\]

除以 \(8.64\times10^{19}\) FLOPs/PF-day 得约 3637.5 PF-days，与表 D.1 的 \(3.64\times10^3\) 舍入值一致。**PF-days 不是 GPU 天；运算量不是电耗；一次模型训练估计也不是整个研究的总成本。**

若只将 175B 个参数各存 2 字节，权重约 350GB（326GiB），尚未计入 KV cache、中间激活、梯度或优化器状态。这是权重存储量的估算。（PDF 9、43、46）

## 评测管线本身也是方法的一部分

### 7.1 示例从哪里来

一般对每道评测题，从任务训练集随机取 \(K\) 个完整输入—答案示例，示例间以换行分隔，再放入待答题。LAMBADA、StoryCloze 使用开发集提供演示、测试集评分；原版 Winograd 缺少独立训练集，演示从同一数据集中抽取，独立性条件应另记。本文没有提供足够实现证据，让核对全部抽样排除规则。

有独立 dev/test 时，作者会在 dev 上试少数几个 \(K\)，再用选定值测 test。不能把它描述为“完全没有任务层面的选择”。SuperGLUE 用 \(K=32\)；WSC、MultiRC 对所有题使用同一组抽中的示例，其他 SuperGLUE 任务通常逐题重抽。（PDF 10、18–20）

这里的 \(K\) 是**每次上下文中的演示数**。逐题重抽可能累计访问更多不同的带标签样本，不能把它解读成“整个评估只接触过 32 条训练数据”。图 3.8 的“8 任务合计 256”也应结合这一抽样规则理解。

上下文长度还限制了示例预算。教学算例：若指令 64 token、待答输入 128 token、预留输出 64 token，每个示例连分隔符共 32 token，则：

\[
K_{\max}=\left\lfloor\frac{2048-64-128-64}{32}\right\rfloor=56.
\]

这是假设等长示例的演示，不是重建作者所有任务的裁剪规则。

### 7.2 选择题不是随便生成一个字母

作者对候选完成文本计算语言模型似然。多数选择题按 token 长度归一化；ARC、OpenBookQA、RACE 等在 dev 上发现使用下式更好：

\[
\frac{p_\theta(a\mid c)}
{p_\theta(a\mid c_{\rm generic})}.
\]

其中通用答案上下文是类似“Answer:”的字符串。对数域中，它是两项 log-likelihood 之差。直观上，减去“这个答案本来就很常见”的影响；比值自身不是正确率。

**独立教学例：**A、B 的条件概率分别是 0.12、0.08，通用答案概率分别是 0.10、0.02。原始似然选 A；比值分别为 1.2、4，改选 B。模型参数完全没变，评分规则已经能改变最终答案。

长度归一化也能改选择：一个 token 的 A 概率 0.55；两个 token 的 B 条件概率各 0.70，则原始序列概率是 0.55 对 0.49，A 胜；每 token 几何平均是 0.55 对 0.70，B 胜。

Winograd/Winogrande 的 partial evaluation 又不同：固定后续文本，替换代词所指实体形成不同上下文，再比较同一后续文本的概率。不能把所有任务都写成同一种“生成回答”实现。（PDF 10、53–54，图 G.13–G.14）

### 7.3 自由生成和指标

自由完成任务采用文中给定的 beam search，beam width 4、length penalty 0.6，再按任务计算 F1、BLEU、exact match 等。开放式诗歌等生成样例另有采样设置，不能把这一 beam 配置套到全部图例。

隐藏测试集并非全部成功提交：很多模型/设置只报 dev；SuperGLUE、TriviaQA、PIQA 有最大模型 few-shot 的测试服务器成绩。看表 H.1 时，要分清普通 175B 列和最右侧 test-server 列。（PDF 10、63）

## 合成任务与生成样例：有趣，但证据层级不同

### 9.1 算术

每个任务生成 2000 个随机问题，以答案完全正确评分；few-shot \(K=50\)。所谓“两位数”实际从整数区间 \([0,100)\) 抽样，也包括一位数和零。不是穷举所有加法，更不是形式化的算法正确性证明。（PDF 21–23、63）

| 运算 | Zero | One | Few |
| --- | ---: | ---: | ---: |

### 9.2 字符操作

五类任务为循环移位、保留首尾的乱序、保留首尾两个字符的乱序、插入符号后恢复单词、倒序单词恢复。每类 10000 例，使用高频且长度在 4 与 15 之间的词，few-shot \(K=100\)。

表 3.10 的 few-shot 分别为 37.9、15.1、39.7、67.2、0.44。尤其倒序恢复几乎失败，说明“模型写得流畅”与“可靠执行字符算法”相距很远。BPE 不是逐字符输入；但它是否就是失败的原因，本文没有完成充分因果消融。

移位和乱序的逆映射还可能不唯一；只接受词表中的一个目标单词，会把部分其他合法还原算错。正文与表 3.10 的若干数值不同；附录 C 另注明它使用不同演示抽样种子，不应把 C 表差异全部当排版错误。（PDF 23–24、45、63）

SAT 类比题共 374 道，zero/one/few 为 53.7/59.1/65.2，few-shot \(K=20\)。与文中人类平均 57% 比较时，应注意样本、先前训练经历和评估条件，不等于通用类比能力超越人类。

## 数据污染：本文最需要批判阅读的部分

### 10.1 训练前过滤与训练后审计不是同一步

训练前：检查评测 dev/test 与语料的 13-gram 重叠，以小写、空白切词并去标点；删除碰撞片段及周围 200 字符，太短的碎片丢弃，切成超过 10 段的文档整篇删除。出现于超过 10 篇训练文档的常见 13-gram 被忽略，以减少模板文字等误报。长文档处理存在 bug，所以没清除全部重叠，作者因成本未重训。（PDF 9、31、43–44）

训练后：按数据集选 \(N\)，依据例子词数的第 5 百分位，再将普通任务限制在 8–13；合成短任务可更短，例如字符任务的 \(N=2\)。任何一个 N-gram 与语料碰撞就标 dirty，否则标 clean。这里比对的是完整候选语料库，不只是实际被训练采样到的部分。

因此这项检查既会误报，也可能漏掉改写和语义等价泄漏。clean 的含义是“该规则未检出碰撞”，不能升级为绝对没见过相关信息。

### 10.2 几个具体结果

| 对象 | 原文审计发现 | 可支持的判断与限制 |
| --- | --- | --- |
| PIQA | 表 C.1 为 dev 全集 82.3，clean 79.3；526/1838 被标 dirty | 下降 3.0 个百分点，约 3.65% 相对下降；保持星号。表 3.6 的 82.8 是 test，别混用 |
| Winograd | 表 C.1：273 题中 164 dirty、109 clean；88.6→86.2 | 确有原题进入语料的证据，保持星号；正文污染比例与表内计数不一致 |

污染标记与分数差是观察性证据。设有一个**人为教学反例**：clean 题本来就容易，不靠记忆准确率 80%；dirty 题本来只有 60%，记忆贡献加 20 个百分点；最后两组都为 80%。观察到“clean 与 dirty 同分”，仍不能排除记忆收益。这不是断言 GPT-3 实际如此，而是解释作者也承认的选择偏差问题。（PDF 33）

### 10.3 比原文更可靠的后续实验应怎样设计

若做课程实验，应先冻结训练/演示/验证/测试划分，记录文本去重规则与语义近重复检查，固定提示后再看测试；还可加入训练截止后或私有新编的题目，使用变化后的实体、数值和组合模式。仅对公开集删除 N-gram 重叠后再测一次，不足以独立识别记忆的因果贡献。这是本笔记的实验建议，未执行。

## “人类难辨新闻”究竟测了什么

短新闻实验从 Newser 选 25 个标题和副标题，给模型提供新闻示例后生成文章。附录 E 说明每个标题生成 5 个候选，自动选与人类文章词数最接近的那个。因此不存在人工逐篇挑最好文本，但仍有按长度的程序选择。

每个参与者看到约一半人类文章、一半生成文章，回答从“很可能人写”到“很可能机器写”的五级选项。准确率计算为**正确判断数 / 非中立判断数**，再按参与者统计。普通美国众包参与者被要求不外查，且有排除规则，不代表专业记者逐项核查事实的实验。

表 3.11 的 175B 短文辨别平均准确率 52%，95% CI 为 49%–54%；故意生成得很差的控制组为 86%。表中极小 p 值比较的是模型组与控制组，不是证明 GPT-3 组与随机猜测完全等价。实验也没有检验新闻事实正确率。

长文小实验选 12 篇 Reuters 新闻，平均人类 569 词、模型 498 词，GPT-3 用另一个新闻示例作上下文；辨别率仍报 52%，95% CI 48%–57%。参与者分阶段看文章并有理解问题，和短文设置并不完全相同。（PDF 25–28、46–48）

人类难以辨别文风，能说明该任务下文本外观接近；不能推出内容真实、长期一致、可替代新闻核验。原版参与者总数还有账目不一致，见下一节。

## 局限与 broader impacts 也属于论文内容

作者指出长文本重复、矛盾、常识物理失败、难以解释、推理昂贵、预训练数据效率低，以及下游任务的强弱不均。仅靠 next-token 预测是否足以支持更广泛的目标导向任务，本文没有给出肯定保证。（PDF 33–34）

偏见检查覆盖职业—性别关联、特定提示下的人群/宗教词共现等。它说明**模型输出在这些探针下表现出偏差**，不能转述为对真实群体的性质判断。作者也承认只考察了有限类别、部分分析只用二元性别代词，词典情感分数会把历史事件讨论等背景混入评价；这些不是完整公平性认证。（PDF 36–39）

误用讨论涉及高质量文本可能降低欺骗等活动的成本，属于作者在 2020 年的风险分析；其中对行为者活动的观察不是今天的态势报告。能源一节给出的内容生成电量估计也有当时硬件和运行假设，不能作为现时 API 价格或完整碳排数据。（PDF 34–39）

## 自测与最小练习

1. **向模型输入 20 个例子，是否进行了 20 次梯度更新？** 没有。若只是推理，权重保持不变，演示进入条件上下文。
2. **Zero-shot 是否保证模型没有在预训练中见过相同任务？** 不保证；它只约束当前演示数量。
3. **为什么不能只报告 K=32，就说整个实验只访问了 32 条标注？** 因为可以逐题重新抽取演示，累计使用的唯一标注样本可能更多。
4. **为什么同一模型在两种选择题评分规则下能给出不同答案？** 原始似然、长度归一化和通用答案似然校正的排序函数不同，见 §7 的 0.12/0.08 算例。
5. **GPT-3 用 Pre-LN 却仍 warm-up，是否推翻 P349？** 不构成推翻；“某些条件下可移除”不是“所有配置都不应使用”。
6. **两位加法 2000 题全对，是否证明学会了可靠的任意位数加法算法？** 不是；样本有限，位数外推结果也显示明显下降。
7. **52% 的人类辨别率是否意味着新闻事实有 52% 正确？** 完全不同的指标。这里衡量人类判断文本来源是否正确。
8. **clean 子集与全集同分能否证明不存在记忆？** 不能；检测规则可能漏检，子集难度可能改变。
9. **哪个数字可以作为 SuperGLUE 的测试总分：73.2 还是 71.8？** 71.8；73.2 是表 H.1 的 dev 汇总。
10. **附录 G 的正确答案能否当作模型生成案例？** 不能。它展示数据集目标与任务格式。

最小练习：不看答案复算 §7 的两个候选排序例子与上下文预算，再用表 C.1 的 PIQA 数据区分“百分点变化”和“相对变化”；最后各选一个强项、一个弱项，写出模型大小、K、split、指标及污染状态。

进阶实验设计：在同一个可用模型上固定私有测试集，比较 K=0/1/4/8、若干预先规定的示例顺序与提示模板；报告验证集选择过程、所有运行、平均值/离散程度、唯一演示样本数、输入 token、耗时及失败案例。它只能是机制性教学实验，除非模型、数据和全部配置吻合，否则不称为 GPT-3 原实验复现。

验收标准：能独立说明“权重不变时发生了什么”、复算评分、识别一次评测口径混用，并解释为何污染检查不能给出绝对保证。参考答案与教学算术见正文。
