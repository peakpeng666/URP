## 1. 为什么需要

用户的 Claude 额度按 5 小时重置，常在任务中途耗尽，然后把工作交给其他 AI（如 ZCode 上的 GLM）或稍后让 Claude 继续。下一位执行者看不到本次对话，只能依靠仓库、桌面文件和提交记录。所以每一步都要能被陌生人接手。

## 2. 留痕：进度文件

位置：`~/Desktop/农业机器人路径规划工作台-第N轮进度.md`。结构：

- 状态清单：每个任务一行，✅ 完成（附提交哈希与一句结论）、⏳ 进行中（附后台命令与输出路径）、⬜ 未开始。
- 后台任务链：步骤顺序、完成标志、中断后的手工恢复命令。
- 交接记录：什么时候把什么交给谁。
- 日志：按时间追加「做了什么、命令、结果数字、提交哈希、后台任务 ID 与输出路径」。

写法：只追加，不改别人的行；数字从结果文件抄，不凭记忆。

## 3. 交接提示词

位置：`~/Desktop/农业机器人路径规划工作台-接续提示词.md`；开新一轮前把旧的归档为 `…-第N轮.md`。内容要能脱离对话独立执行：

1. 背景与目标（一段话）、必须遵守的约束（封存田块、归属边界、不推送、不碰用户未提交的文件、不读 `.env*`）。
2. 现状：已完成的提交表（哈希 + 内容）、正在运行的后台任务及其完成标志。
3. 任务清单（R1、R2…）：每项给出精确命令、输入输出路径、验收标准、已知陷阱、需要写进报告的位置。
4. 收尾：全量测试命令、最终汇报格式（完成项、数字、未完成项、证据路径）。
5. 用户中途提出的新要求，以醒目的「追加」块写进相应任务。

## 4. 与其他 AI 同时工作

2026-10-23 下午，另一个 AI 按接续提示词在同一工作树、同一分支上提交（`power.py`、`figures2.py`、准入规则比较等），与 Claude 的工作同时进行。约定：

- 开工前看 `git log --oneline -15` 与 `git status`，判断谁在动哪些文件。
- 只暂存自己的路径：`git add -- <路径…>`，再 `git commit -m "…" -- <路径…>`，避免把对方已暂存的改动卷进自己的提交。
- 不改对方正在写的文件；需要对方配合（如统一术语）时，写进进度文件和接续提示词的对应任务。
- 共享的索引或汇总文件采用合并写入：读出现有内容，只替换自己负责的条目（`figures.write` 合并 `figures/index.json` 即为一例）。
- 归属于提示词任务的产物（如账本重建、报告第 7 节）留给对方，避免两边同时写同一文件。
- 用户自己的未提交改动（`literature/`、`papers/补充/`、`src/lab/.gitignore`、两个 `.bat`）一律不动。

## 5. 复核其他 AI 的报告

报告是线索，不是证据。逐条对照代码、运行结果和数字：

- 第 2 轮复核纠正过的结论：「44% 的路径存在盲区」（加密检验过严，圆角检验显示约 15%）；「预登记」措辞（规则未冻结，改为「事先写定」）；多车选择余量（几何容差造成的假象）；静态门控方向；`admission._cv_policy` 中 `X=None` 的缺陷。
- 复核方法：重跑关键数字的最小命令；看结果文件的分母与检验种类；检查是否误用封存田块；检查晋升判定是否按事先写定的准则。

## 6. 提交与推送

- 工作分支 `evolve/decision-loop-20261023`，`main` 是完整集成基线；不用 reset、强推或批量删除；`backup/*` 是历史快照。
- 每完成一项就提交，信息写清做了什么和结论；提交信息末尾带协作署名（按会话提示）。
- 推送与开 PR 需要用户同意。
