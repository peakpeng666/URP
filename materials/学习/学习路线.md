## 先知道自己在做什么

我们的方向是：**让电脑提出算法，用真实运行判断算法好不好，再改进它。** LLM 提出代码只是其中一步。你要学会提出清楚的问题、写评测器、比较算法，最后把这些组合成可信的研究系统。

以装箱为例：容量为 10 的箱子，要按到达顺序装入大小为 6、4、5、5 的物品。**实例**是这串物品和容量；**解**是物品放在哪些箱子；**目标**是少用箱子；**约束**是不能超容量；**算法**是每来一个物品怎样选箱子。LLM 可以写出选箱规则，但规则实际用了几个箱子，要由另一个程序运行检查。

先用两天建立可以复述的知识地图、看懂核心例子，再按完整路线完成代码、训练、复现和报告。老师的要求和逐项验收保留在学习对照中。

路线按**每天 6 小时、每周 5 天**设计，可按实际可用时间拆分。每阶段按验收推进，以下周次表示学习顺序。

## 先学这 18 个词

| 词 | 普通话解释 | 在我们项目里的例子 |
| --- | --- | --- |
| 算法 | 可以重复执行的解题步骤 | 总把物品放进放得下且最紧的箱子 |
| 程序/代码 | 把步骤写成电脑能执行的形式 | Python 的 `choose_bin` 函数 |
| 实例 | 一次具体要解的数据 | 某一串物品、某一块农田 |
| 解 | 对这一次问题给出的安排 | 箱子分配、作业路线 |
| 目标函数 | 用数字表示好坏 | 箱子数量、总作业时间 |
| 约束 | 必须满足的条件 | 不超容量、不越界、不撞障碍 |
| 启发式 | 通常有用、但不保证每次最优的规则 | 最近邻、best-fit |
| 基线 | 用来比较的已知方法 | 人工 best-fit、随机搜索 |
| 搜索空间 | 所有允许候选组成的集合 | 可选规则、代码片段、网络架构 |
| 种群/个体 | 同时保留的一批候选/其中一个 | 多份候选启发式代码 |
| 适应度 | 搜索时用来筛选候选的分数 | 在训练实例上的平均用箱数 |
| LLM | 根据上下文生成文本的模型 | 根据函数说明生成代码 |
| Prompt/Token | 给模型的输入/模型处理文本的基本单位 | 函数签名、约束和失败反馈 |
| 推理/微调 | 使用已有权重生成/用数据更新权重 | 生成排序代码/训练 LoRA 参数 |
| NAS | 自动搜索神经网络的结构 | 选择 CNN 层数与通道数 |
| 强化学习 | 根据行动后的奖励调整策略 | NAS 控制器更常提出验证表现好的架构 |
| 验证集/测试集 | 选择方案用的数据/最后评价用的独立数据 | 不能反复看最终测试结果再改提示 |
| 消融/泛化 | 拿掉一组件看作用/换新实例还能否有效 | 去掉反思；换田形和转弯半径 |

“模型”有两种常见含义：神经网络模型和数学优化模型。数学模型写变量、目标与约束；神经网络模型有可学习的权重。看到 model 先确认说的是哪一种。

### 装箱的手算例

容量 10，物品依次到达 `[6, 4, 5, 5]`：第一个箱子放 6，再放 4，正好满；第二个箱子放 5，再放 5，共 2 个箱子。总大小 20，至少需要 `ceil(20/10)=2` 箱，因此本例达到下界。下界在一般实例上未必可实现。

再看一个单步选择：已有三个箱子剩余空间 `[8, 5, 2]`，新物品大小 4。可行箱子是前两个；best-fit 选剩余 5 的箱子，放后只剩 1；first-fit 若按列表顺序，则先选剩余 8 的箱子。谁最后用箱更少，取决于后续实例，不能凭这一步的直觉证明。

在线规则这一步能看当前物品与已开箱状态，不能看未来物品。评价程序可以在后台拥有完整序列并逐步喂给规则；**不应把完整序列传给决策函数**。

### GA 的手算例

只优化一个数，使 `f(x)=x²` 尽量小。候选 `[-3, 1, 4]` 的代价为 `[9, 1, 16]`，其中 1 最好。给保留的候选做小修改，例如得到 0.8，再计算 `f(0.8)=0.64`，才能说新候选有改善。这里“进化”的是数字；在 EoH 中，候选变成一段算法代码，而代码要在许多实例上运行后才有分数。

### 两天自测，先答后看提示

| 题 | 合格答案必须包含 |
| --- | --- |
| 1. LLM 写出一段代码，为什么还没完成算法设计？ | 代码要可执行、满足约束、有可比较质量；还要搜索/选择、独立评测 |
| 2. GA 与 EoH 都在进化，个体分别可能是什么？ | 数值向量/解，与算法规则代码；评价对象不同 |
| 3. 为什么不能把最好的一次成绩当总结果？ | 随机性、选择偏差；需要多次独立搜索与汇总 |
| 4. temperature 改了，是微调吗？ | 不是；只是采样参数；微调会更新可学习权重 |
| 5. NAS 与代码生成有什么关系和不同？ | 都能是搜索；NAS 搜神经结构并训练评估，代码生成输出程序 |
| 6. EoH 生成的 best-fit 变体在哪些数据上得分？ | 搜索用训练实例、选方案用验证实例，最终独立测试保留 |
| 7. 在线装箱能否先把物品从大到小排序？ | 不能，这改变为离线问题；除非明确更换问题定义 |
| 8. 路线更短，是否一定是更好农业方案？ | 还要看覆盖、边界、障碍、转弯、作业时间及任务约束 |
| 9. 算法选择与算法生成分别交付什么？ | 前者从已有算法中选择；后者生成/修改算法，可组合但不能混写贡献 |
| 10. 老师 P4、P5、P6 分别必须有什么？ | RL+CIFAR-10；多问题系统+对比；新假设+实验+论文 |

若 1–6 题解释不清，先回到手算例和模型权重那张卡；若 7–10 不清，先看问题定义和验收表。用错题决定下一步，不靠继续下载论文缓解焦虑。

## 每篇论文怎样读，才能转成项目能力

第一遍 20–30 分钟：标题、摘要、主图、结论，写五句——解决什么、输入是什么、输出是什么、改哪里、怎么证明。第二遍 60–90 分钟：方法与实验，画伪代码，查对照、预算和测试集。第三遍：找到代码的配置、入口、候选接口、评测器，跟踪一个实例。只有第三遍加独立小修改后，才记为“能用于实现”。

统一笔记模板：`问题 / 与老师哪项对应 / 前置知识 / 核心方法 / 我读到的原文页节 / 可借用代码 / 实验限制 / 一个最小复现 / 下一步`。不懂英文先逐段解释术语，再回到图和代码；不要让翻译代替判断。

## 与最后完成项目的关系

P1 学会搜索与评分；P2 学会模型生成程序与测试；P3 学会迭代改算法；P4 学会搜索一个需要训练才能评价的对象；P5 把共用部分做成多任务系统；P6 让一个明确的新方法接受严格比较。农业路径规划接在已有可靠接口后面，提供真实约束与应用价值。P4 即使不进入农业运行流程，也必须完成，它是老师明确要求的一部分。

你的最终产物应包含算法、数据协议、实验结论与可复现系统。展示界面可以帮助别人使用和理解它，但研究闭环必须已经真实运行。
