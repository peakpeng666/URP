# 研究计划

按老师近期反馈，先完成**经典CVRP不同规模与分布下的已有基础算法对照**，整理可用于中期答辩的结果；基于正式对照再判断算法改进与智能推荐收益。与此同时，按用户与负责人要求，中期交付一套可运行系统：任务导入、算法选择/推荐、受控运行、独立验算、二维展示、现成环境仿真及证据导出并行建设，不等科研改进完成后再做系统。农业分布、作业约束和更广路径任务同步调研。

现用方案：[系统交付与验收](中期系统交付与研究对齐.md) · [路径研究全景与证据](路径研究全景与证据.md) · [路径与仿真总方案](路径研究与仿真方案.md)。以下章节按工作主题排列，不表示串行等待。正式53例尚未运行、前后端闭环和真实仿真尚未完成；本次更新只修订研究与交付安排。

## 1. 先完成CVRP分层基线对照

从老师提供的[CVRPLIB入口](https://galgos.inf.puc-rio.br/cvrplib/en/instances)选取经典算例。先核对复用现有输入、源码和结果；小、中、大规模及分布分组、实例清单、算法版本和预算协议在新实验前冻结。

| 工作 | 具体安排 |
|---|---|
| 实例与分层 | 按客户数划分小、中、大分组；按来源说明和坐标、需求、容量特征记录分布，排查重复底本。保存原文件、来源及哈希，标明每层实际覆盖 |
| 已有基线 | 先比较现有且支持对应CVRP约束的基础优化算法，保留成熟求解器质量参照；冻结算法、配置、初始化、种子和停止条件 |
| 统一评价 | 明确客户恰好服务一次、容量、仓库、车队语义和距离取整；同一比较使用统一预算与输入权限，独立复算可行性及成本 |
| 结果与成本 | 分层报告计划次数、可行率、质量、CPU、墙钟及失败；来源可靠且目标、约束和计分一致时计算参考gap，保留参考值的BKS或已证最优标签 |
| 中期材料 | 整理已有实验、基线差距、失败与适用条件，每个数字链接原始结果；新增结果取得后再并入 |

CVRPLIB接口、小例、预算停止和独立验算已通过2026年10月14日[运行前验收](../experiments/CVRPLIB入口.md)，VND原归档来源也已闭环。下一步另行冻结正式算法、实例、预算、种子和运行登记表，再按冻结清单运行；正式批次尚未启动。已有公共小16题、大X及预算敏感性结果提供准备依据；新比较另设运行ID，区分同预算比较和已有跨预算质量参照。第一步保持已有算法主体，先测清基线与问题差异。

现有依据：[公共强基线](../experiments/reports/路线求解/公共路线强基线.txt) · [大X实例](../experiments/reports/路线求解/公共大X实例迁移.txt) · [预算敏感性](../experiments/reports/路线求解/公共强基线预算敏感性.txt) · [数据入口](../data/README.md)。

## 2. 在强基线上研究改进与智能推荐

依据第一阶段结果选定有竞争力且仍有改进空间的基线，再确定一项具体机制：LLM修改受限算法组件，或根据可用实例特征选择算法。先比较训练侧选定的单算法SBS、简单规则或选择器，再检验生成候选的增量，计入生成、特征、选择、求解和回退成本。

新增算法的准入方式是一个可检验方向：固定共同候选池、初始算法库、选择器、库容量和总评价预算，比较以下四种依据（第四项将既有 Hydra 近邻落实为强对照，并非声称新发明）。

| 准入方式 | 判断依据 |
|---|---|
| 单成员成绩 | 候选在开发实例上的平均表现 |
| VBS增量 | 加入候选后逐实例最优组合的改善 |
| 实际选择收益 | 加入候选并重训选择器后，在独立验证组上的净改善 |
| 当前策略残差 | 围绕旧策略损失配置候选，入库后按同预算更新选择器 |

另设旧库获得同等额外调参/标注预算的对照，区分扩库收益与更多拟合成本。共同候选池只能检验准入策略；真正生成反馈的作用须另外在完整闭环中验证，不能混称共同进化。库更新后重新绑定模型、特征、预算和校准版本。

同时报告五个对照：旧库策略、训练集选定单算法SBS、新成员单独、新库VBS和新库实际策略。VBS是逐实例事后最佳结果，部署收益由实际策略衡量；选择器先采用简单基线。

开发数据分为候选评分、选择器拟合与准入验证三部分；样本有限时采用按来源分组的交叉拟合。最终测试在方法和参数固定后使用。CVRP与TSP按原始实例及重复底本分组，装箱按序列与生成族分组，农业按原始田块分组；同一对象的顺序、旋转和尺度变体归在同组。

记录模型请求/token、候选评价次数、执行CPU/墙钟、选择器拟合/特征/推断成本及失败与超时。独立重复完整生成流程，区分外层搜索和实例重复；先比较可行率，再比较质量与成本。

继续推进的判据是：实际策略在预定预算和新实例上获得稳定收益，消融能定位到准入机制。仅VBS改善时分析误选与特征；候选缺少互补性时先改生成目标。定义与近邻见[算法生成与实际选择](../literature/专题/算法生成与实际选择.md)、[评价预算与实验设计](../literature/专题/评价预算与实验设计.md)。

## 3. 并行交付路径系统与复用P5组件

装箱、TSP及已有路线宿主用于复用生成、候选管理、预算、执行、记录和导出组件；本轮独立CVRPLIB入口已完成输入、路径、Linux x86_64/Python 3.12离线环境、小例和独立验算。接下来冻结正式分层基线对照计划；该专项验收不替代用户主机实装、全库回归或历史检查记录。

| 工作 | 现有基础 | 后续接入 |
|---|---|---|
| 装箱宿主 | [装箱组件](../experiments/results/组件/online_bin_packing)、[演化结果](../experiments/reports/装箱演化/装箱演化与新数据验证.md) | 评分函数适配器；FF、BF和公开EoH共用输入与检查 |
| TSP宿主 | [GLS实验](../experiments/results/搜索机制/TSP引导局部搜索/实验报告.md) | 固定构造与2-opt宿主；开放一个评分或扰动组件 |
| 生成与候选 | [生成器](../src/research/generator/README.md)、[父代回放](../experiments/results/搜索机制/父代选择离线回放) | 新实验配置、生成器接口、父代与提示记录、候选源码哈希 |
| 执行与检查 | [研究CLI](../src/research/README.md)、[进程监督](../src/research/execution/README.md) | 统一结果结构，记录解析、接口、超时、可行性和数值失败 |
| 记录与展示 | [后端API](../src/backend/api.md)、[前端](../src/frontend/README.md) | 同一运行包可导入后端，界面查看候选、预算、结果与证据 |

中期主系统须从真实任务到运行、检查、二维界面、现成环境仿真和导出闭环，并通过取消、重启、失败和干净安装验收。现有 runner 不支持同监督器并发，也不是任意生成代码的安全沙箱；接入必须保留其合同。P5跨任务整合单独签收，主系统通过不等于P5完成。

P5继续以同一入口在多个问题上完成生成、执行、反馈、候选更新、新实例测试和结果导出为目标。装箱与TSP用于已有组件回归和多问题扩展；新生成按明确的模型、调用预算与独立输入另建运行ID。

## 4. 农业映射与后续验证

同步分析CVRP的空间、需求及容量特征如何对应农业任务，确定服务模型、任务集合、车队与运动连接。现有124田实验研究固定合成任务的距离代理和容量；车具、服务方向与Dubins实验提供可复用机制。下一阶段选定一个农业模型开展验证，再扩展覆盖或车辆运动约束。[农业任务定义](../literature/专题/农业任务与服务模式.md) · [农业结果](../experiments/reports/农业路径) · [服务与运动](../experiments/reports/服务与运动)。

基础练习、程序合成、AlphaCode机制和微调实践按[学习对照](../materials/学习/老师要求与进度.md)继续推进。
