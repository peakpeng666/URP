## 已有结果

[CVRP 主基线](../experiments/baselines/cvrp/README.md)已按 [冻结计划](../protocol/formal_plan.json)完成 **17 配置 × 53 问题 × 5 种子/重复 = 4505 项**。归档重审确认，4316 项独立验算可行，189 项无有效解。53 个问题来自 51 个底本，主计划分母保持 4505 项。PyVRP 是当前强固定基线。[vendor 120 项](../experiments/baselines/cvrp/evidence/vendor_all120_audit.json)、[李月莹接手验收 742 项及两批各 48 项](../experiments/baselines/cvrp/handoff/20261016-liyueying/核验与接手.md)按各自预算和目的独立记账。

工作台已具备任务输入、算法建议与求解、独立验算、二维显示、限定车型 Gazebo 执行和导出能力。现有证据覆盖规划与限定条件下的仿真执行；真实农机作业质量和并行多车效率需要相应的实地与控制实验。

学习选择器已有 train60/cal30/test30 实验。120 项严格成本比较中，PyVRP 在训练集为 51 胜 9 平、校准集为 23 胜 7 平、测试集为 27 胜 3 平；OR-Tools 严格更优 0 项。测试结果尚未显示相对固定 PyVRP 的选择收益。较早的 [24 合成实例 CRC 回放](../src/research/docs/RESEARCH_ACCEPTANCE.md)保留为独立实验。

- **发布版本。** 镜像快照基于 `ddb5113e…`，此前静态审查对应 `23fafe4…`。容器 warehouse 0/5、原生同场景 5/5 及 GUI 限制按原版本记录。核对 Fuel 缓存附件的实际内容与许可，再统一附件清单和第三方分发说明。详见 [平台快照](../setup/2026-10-18/platform-snapshot/summary.json)与 [第三方说明](../deploy/THIRD_PARTY.md)。

## 3. 确定论文主线与评价判据

### 智能选择收益

先在开发资料上检验候选算法的互补性。当前 120 项同预算比较中，OR-Tools 从未严格优于 PyVRP，下一轮实验需要先确定有研究价值的新候选或新分布。

实验预先固定候选集合、强基线及完整成本核算，包括特征提取、选择、求解与回退。候选和门控参数在开发资料上确定；开发、校准与冻结测试按原始 CVRPLIB 底本或农业原田块分组隔离。

主要结果报告可行率、成本、失败情况，以及实际策略相对固定强基线的净收益。VBS 用于衡量候选库的潜在上界，独立测试净收益与消融结果共同作为方法成立的依据。背景见 [算法生成与实际选择](../literature/专题/算法生成与实际选择.md)及 [评价预算与实验设计](../literature/专题/评价预算与实验设计.md)。

### 农业任务改进

先选定一种具体服务语义，例如采样或喷洒，明确作业具可达范围、幅宽、停车与补给耗时，以及车辆运动合同，再确定任务集与对照。

真实田块边界与合成点位构成受限代理任务，结论对应这一输入范围。实地作业质量另由真实执行数据评价。

若比较多车工期，规划指标需与实际串行预约方式一致；并行效率则通过独立的交通与控制实验评价。计划 makespan 和实际耗时分别记录。资料见 [农业任务与服务模式](../literature/专题/农业任务与服务模式.md)及 [已有农业结果](../experiments/reports/农业路径)。

### 候选生成与算法库更新

LLM 候选生成作为独立研究课题，采用离线生成、固定预算评价、独立检查、候选准入、选择器重训和未见测试的完整流程。具体设计见第 5 节，核心评价对象是更新后实际策略的净收益。

## 4. 工程版本与回归

当前工程修复及实际回归范围以 [2026-10-19 交付复核](../setup/2026-10-19/delivery-review/REPORT.md)为准。`23fafe4f…` 静态审查中的源码绑定、第二网关、推荐有效域和 `fleet_limit` 问题保留为此前版本的审查记录。

后续发布按以下合同核验：

- **执行身份。** 运行记录绑定提交和实际执行源码，同一运行库的网关访问遵循互斥规则。
- **推荐有效域。** 推荐记录绑定预算、种子与重复次数、距离规则、特征及模型身份。每算法 0.25 秒、两次重复之外的配置单独标注验证状态。
- **车辆上限。** 转弯服务 mode 明确 `fleet_limit` 的支持范围；支持时按合同约束求解，暂不支持时拒绝非空上限。历史无上限面板按原输入合同解释。
- **回归范围。** 源码变更使用新提交、针对性反例与回归记录。代码回归、全量平台验收和 ROS / Gazebo 物理复验分别留存证据，并绑定各自版本。

旧基线、旧模型评估和旧物理会话保留原证据等级；[历史失败](../experiments/failures.md)与冻结实验继续归档。

中期材料围绕一条明确的核心命题组织。装箱、TSP、多问题生成循环及通用车辆、并行控制列为扩展方向。

## 5. 后续实验协议草案：候选生成、准入与选择

本节为新实验的协议草案，冻结后执行。

从具有竞争力和互补空间的旧库出发，固定共同候选池、初始算法库、库容量、评价预算、输入权限与验算器。LLM 的修改范围限定为算法组件，使用开发阶段允许的输入；测试标签保持隔离，预算、checker 与评分合同保持固定。

### 四种准入规则

| 准入规则 | 开发阶段的决策依据 |
|---|---|
| 单成员成绩 | 候选自身的平均表现 |
| VBS 增量 | 候选入库后，逐实例事后最优上界的改善 |
| 实际选择收益 | 候选入库并重训选择器后，在独立准入验证组上的净收益 |
| 当前策略残差 | 根据旧策略损失配置候选，再以相同预算更新选择器并核验收益 |

旧库获得同等额外调参与标注预算，用于区分准入机制的作用与额外拟合资源的作用。

共同候选池实验评价准入策略；完整闭环实验评价生成器如何根据反馈产生新候选。两类实验分别报告。算法库变动后，重新绑定候选源码、特征、模型、预算与校准版本。

### 五种对照

至少并列报告：

1. 旧库实际策略。
2. 训练集选定的单算法 SBS。
3. 新成员单独运行。
4. 新库 VBS。
5. 新库实际策略。

VBS 表示事后上界。主要结论依据实际策略相对固定强基线的可行率、质量与净成本，并纳入简单选择器对照。

若改善只出现在 VBS，重点分析误选和特征；若候选缺少互补性，在开发阶段调整生成目标。冻结测试用于评价已确定的方法与参数。

### 数据划分与来源隔离

开发资料分为候选评分、选择器拟合和准入验证三部分。样本较少时采用按来源分组的交叉拟合。最终测试在方法、参数、候选库与主要指标固定后启用。

分组规则如下：

- CVRP / TSP 按原始实例及重复底本分组，序列顺序、旋转和尺度变体归入同组。
- 装箱按原始序列与生成族分组。
- 农业按原始田块分组。

同一组完整归入同一划分，训练、校准与测试保持来源隔离。历史使用过的 53 个问题按已使用数据登记，未见测试采用独立的新实例来源。

### 预算与继续推进判据

完整成本包括：

- 生成模型请求与 token。
- 候选评价次数。
- 执行 CPU 与墙钟时间。
- 特征提取、选择、重训、求解和回退。
- 失败、超时与无有效解。

外层生成流程独立重复，以独立搜索过程作为生成试验的重复单位；同一搜索中的实例重复用于评价该次搜索的表现。

继续推进的判据为：实际策略在固定预算和新实例上取得稳定净收益，且消融能够定位准入机制的贡献。VBS 和演示例改善用于诊断与分析。

设计背景见 [算法生成与实际选择](../literature/专题/算法生成与实际选择.md)及 [评价预算与实验设计](../literature/专题/评价预算与实验设计.md)。
