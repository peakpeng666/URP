# 按需取用

从[GitHub 仓库](https://github.com/peakpeng666/URP)或[云盘](https://drive.google.com/drive/folders/1ZpHAznk36B-PVwL19lo_-kulRF3pwtBY)取得当前项目。GitHub 当前为公开仓库。源码、精读、论文原文、教材和数据使用相同的项目相对路径；平台环境和大型运行数据另见 [setup/README 的 Release 快照恢复](../setup/README.md#平台快照下载与恢复)。

## 取得项目

```sh
git clone https://github.com/peakpeng666/URP.git
cd URP
```

已有本地仓库时，先检查未提交修改，再正常更新，不覆盖本地工作：

```sh
git status
git fetch origin
git pull --ff-only
```

曾启用稀疏检出的工作区可执行 `git sparse-checkout disable` 取回完整已跟踪目录。

从云盘下载完整文件夹后，在Ubuntu/WSL的项目根目录运行 `python3 tools/restore_links.py`，恢复4个本地目录链接。Git检出会保留这些链接；云盘目录本身不能表示POSIX符号链接，脚本不会覆盖已有不同文件。

## 阅读与复核

- 论文原文：`papers/`；教材：`literature/教材/`
- 精读和本地阅读器：`literature/README.md`、`literature/阅读目录.html`
- 实验报告与原始记录：`experiments/目录.md`、`experiments/results/`
- 数据和派生库：`data/README.md`
- 文件来源与核验记录：`experiments/provenance/`

## 启动

唯一使用入口为 [setup/README](../setup/README.md)：工作台统一使用 4100，启动、停止、依赖准备与仿真演示均在该处维护。

派生数据库与面板导出由原始记录构建；测试结果及来源清单位于 `data/backend/` 和 `data/bpp/audit/`。数据重建与新实验分别记录。

研究以当前目录内的实现、数据和证据为准。后续工作见[研究计划](下一阶段.md)，已撤回结论与失败边界见[科研纠错](../experiments/research_corrections.md)。
