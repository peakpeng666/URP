# 中期系统交付与研究对齐

更新：2026-10-14。本文是交付定义与研究安排，不是新增实验或系统已经完成的声明。

## 1. 两项要求同时成立

用户与负责人已明确：**中期就要交一套系统。** 因此不能把中期产物降格为文献综述、实验表格、静态页面或若干互不相连的脚本。

用户于北京时间 2026-10-13 转贴的老师要求是：在 CVRPLIB 的不同规模、不同分布上先运行已有基础优化算法，构造基线；再依据结果选择好的基线研究改进，同时思考通用数据分布与农业场景的结合。

两者不是二选一：**系统工程、标准基线、广泛研究并行，结果在统一接口和证据库汇合。** 不以时间紧或本科身份裁剪研究上限，也不以长期宏大架构替代中期可操作系统。

项目只考虑仿真，优先官方及成熟社区资源，不涉及实机、采购或现场部署。当前仍未获准启动 Codex，研究范围扩大不改变这一边界。

## 2. 中期系统究竟要能做什么

以下是依据“路径和仿真都要”的现有要求制定的交付建议：主系统包含至少一套现成官方/社区环境的真实仿真接入，具体平台和任务合同待静态筛选及运行验收后冻结。不是所有候选平台均须交付。P5 跨任务生成系统单列研究整合里程碑，不在没有明确依据时冒称老师要求其全部必须中期完成；其完成与否须单独披露。

按下面的完整使用流程验收，而不是按软件截图数量验收：

**选择或导入任务 → 检查问题定义 → 查看算法能力和推荐依据 → 提交运行 → 查看进度并可取消 → 独立检查结果 → 二维交互比较 → 执行已验收仿真任务（另设历史回放入口） → 导出可复核报告。**

| 模块 | 中期交付应呈现的能力 | 验收方法 | 当前已确认状态 |
|---|---|---|---|
| 项目和实例库 | 管理实例、规模/分布特征、来源、单位、车队合同；导入支持的外部实例 | 合法输入成功；缺失/不支持字段被明确拒绝；不静默丢约束 | CVRPLIB 53 例输入/参考有独立验收；面向用户的完整流程待接 |
| 算法库 | 列出可调用算法、版本、参数、支持约束；不把代码目录数当已接入算法数 | 不兼容的任务不能运行；可复现算法配置 | 有现成基础算法与运行器；统一产品注册和界面待接 |
| 推荐模块 | 区分固定默认、规则推荐、学习推荐、事后最佳；显示适用条件和回退原因 | 禁用测试标签泄漏；无适用模型时明确说明；不能假造置信度 | 有历史离线选择实验；当前 CVRPLIB 有效学习推荐尚未证明 |
| 受监管运行 | 从界面启动真实计算，记录任务ID、参数、预算、状态、日志；可靠取消/失败处理 | 启动、成功、非法解、超时、崩溃、取消各有测试 | 研究 CLI/独立运行器可复用；现有 Web 后端仍不启动实验 |
| 独立评价 | 重算覆盖、容量、距离、时间窗等适用指标；区分算法、输入与环境失败 | 人工构造漏点、重复、超载、错误距离等反例被检出 | 现有 checker/验收资产较齐，产品链路仍待接 |
| 二维工作台 | 车辆分色、节点和约束、候选对比、路线及指标联动、原始证据入口 | 用户操作改变选择；视图对应真实 run/revision，刷新不丢记录 | 新只读 route-scene 合同及合成夹具已验收；不含前端、历史全档案和物理仿真 |
| 仿真入口 | 对选定的官方/社区环境启动适配任务、显示状态、播放记录，区分规划和执行轨迹 | 不是只打开 RViz；应有明确任务、执行反馈和终态记录 | 资源静态核查与适配夹具存在；实际运行未完成 |
| LLM/算法设计实验区 | 展示并关联生成规格、候选源码、准入、失败、评价和版本；统一生成—演化—评估入口列入建设与独立验收项，未通过不得宣称 P5 完成 | 生成文本不算合格算法；候选必须在受限接口与独立检查下评价 | 已有生成和评估结果，但统一多问题端到端系统仍缺 |
| 导出与复现 | 导出输入、配置、代码身份、结果、检查、日志和报告；保留失败记录 | 另一环境可按锁定配置复核；报告数字能追溯 | 已有证据与版本管理基础，统一产品导出待接 |
| 安装与交付 | Ubuntu 本地启动、依赖说明、离线资源和故障诊断 | 在指定环境从干净安装到演示完整复验 | 用户主机及正式运行环境未验收 |

这张表定义建设目标，不把“待接”模块包装成已完成。中期系统具备推荐功能与“学习推荐显著优于强基线”是两个不同验收问题：前者必须真实可操作，后者必须有实验支持。

## 3. 用同一套接口组织，而不是把软件窗口拼在一起

建议产品核心不依赖某个仿真器，采用以下边界：

- ProblemSpec：任务族、输入、坐标系、目标、硬约束、预算、来源和版本。
- AlgorithmSpec：能力、参数、代码身份、依赖和输出类型。
- RecommendationRecord：推荐类型、模型/规则版本、可用输入、理由、预测及回退；与运行后观测分开。
- JobSpec / JobState：排队、运行、取消中、完成、失败等状态及时间戳；幂等提交、持久事件和受限排队；现运行器同监督器不支持并发，不能直接多线程接入。
- ResultBundle：候选计划、独立检查、代价、耗时、失败分类和完整证据。
- SimulationRecord：环境/模型版本、坐标变换、执行命令、仿真时间、轨迹、接触/越界/任务事件；独立于数学解。

新接口是产品设计建议，不表示目前后端已实现这些写入和运行端点。已有只读接口继续服务历史记录；新增运行能力通过受监管执行层接入，不能让网页任意执行 shell 或任意候选代码。

前端延续现有 React/Vite 工程和既定分工，不另造一套不互通的面板。桌面封装可评估 Tauri 或 Electron，但外壳选择不改变核心数据合同，也不能成为伪装系统完成的手段。若用 Tauri，要核对 Linux WebKit/Rust 依赖；若用 Electron，要遵循进程隔离和权限边界。参见 [Tauri 官方前置条件](https://v2.tauri.app/start/prerequisites/)与 [Electron 安全说明](https://www.electronjs.org/docs/latest/tutorial/security)。本轮未安装或选择最终外壳。

正式计划尚未冻结、正式 53 例多种子比较尚未启动。该状态刚从固定仓库入口重新核对，不是根据旧聊天猜测。[当前 CVRPLIB 入口](https://github.com/peakpeng666/URP/blob/ad80a208e567abd57d6a2c5f99978a88f13abc7a/experiments/CVRPLIB入口.md)

## 5. 展示材料的层级

建议正文围绕五个问题组织，篇幅和形式按学校要求再适配：

1. 我们解决什么：路径任务、农业联系、算法库与推荐的边界。
2. 系统能做什么：从任务到运行、检查、展示与导出的真实操作。
3. 基线告诉我们什么：规模、分布、质量、耗时、可行率与失败，不只放最佳路线。
4. 哪些研究已经有证据：正结果、负结果、适用域和数据限制。
5. 下一步为什么这样做：根据基线和近邻文献提出可检验机制，而非罗列热门名词。

老师 P1—P6 指南中的优化、代码生成、EoH、NAS、统一系统和原创研究分别放入对应成果或附录。P1/P4 教学完成度可证明学习与实现积累，不替代当前路径系统或 CVRPLIB 证据；P5 统一入口仍是实际系统缺口。[老师指南对应进度](https://github.com/peakpeng666/URP/blob/ad80a208e567abd57d6a2c5f99978a88f13abc7a/materials/学习/老师要求与进度.md)

### 必须明确区分的四种演示

- 实时运行：现场提交任务，本次产生结果、日志和检查。
- 历史回放：展示封存结果，必须标出生成日期和运行ID。
- 仿真运行：现成模拟环境实际执行，展示真值/反馈与任务状态。
- 设计预览：尚未接通功能的交互稿，不混入系统验收。

准备历史回放作网络或图形环境故障时的备份是合理的，但不能把备份录像说成现场运行。

## 6. 多AI协作不等于多套互不兼容的系统

以可独立核验的产物划分，而不是让所有 AI 各写一份总方案：

| 工作包 | 输入 | 应交付 | 不应改动 |
|---|---|---|---|
| 数据与分层 | 固定原始实例、来源、合同 | 实例清单、特征字典、分组与重复底本审计 | 原始坐标/需求/参考答案 |
| 基线适配 | 算法源码与固定接口 | 可调用插件、参数与准入测试、依赖锁定 | 冻结算法主体与评分规则 |
| 批次运行 | 冻结任务清单与环境 | 全量原始结果、失败和未启动登记 | 实验中途删差样本或换预算 |
| 独立检查 | 原始输入与候选输出 | 独立成本/约束结果、反例、差异定位 | 不能直接相信求解器自报结果 |
| 系统后端 | 统一任务/结果合同 | 作业生命周期、监督器接线、API与导出 | 不让前端直接执行任意代码 |
| 二维前端 | 冻结API和夹具 | 可操作界面、真实状态与证据链接、视觉验收 | 不重算不同口径的“权威成本” |
| 仿真适配 | 固定上游版本、任务与模型 | 加载、坐标/话题适配、任务执行与记录 | 不把基准单位擅自当米 |
| 研究方法 | 公平基线与隔离数据 | 选择/配置/生成的具体假设与消融 | 不使用最终测试反馈调参 |
| 农业映射 | 原始场景证据和任务定义 | 可检验映射、边界与对照场景 | 不根据外观或名称捏造农艺含义 |
| 总体验收 | 所有模块和冻结测试清单 | 从干净启动到完整流程的独立验收 | 不把模块测试数量当产品通过 |

每个包共同携带 problem_id、revision、contract_id、algorithm_id、run_id、输入/源码哈希、单位和状态枚举。写代码的产物应由另一路审查；多个 AI 得到相同结论不替代原始证据。

## 7. 本轮分析的执行边界

本轮继续全量调研和设计，中期交付目标已经升级为完整系统。没有因此宣称现有只读原型变成了完整系统，也没有擅自启动正式实验、付费调用、Codex 或用户电脑任务。

待统一的具体信息包括中期检查日期、学校模板和现场演示环境；这些未知不阻止现在的全面研究、接口设计和并行任务划分，也不作为压缩研究范围的理由。

## 8. 交付签收与不可替代的证据

中期系统的必交核心是：固定发布版本、可安装工程、当前 CVRPLIB 导入和算法注册、真实运行与独立检查、可操作二维工作台、推荐或明确回退、完整失败登记、可迁移导出，至少一套选定现成环境的真实仿真任务，以及已有生成实验档案与版本证据的关联展示。在线生成执行和 P5 多任务统一演化是单列能力，不能以档案展示声称完成。官方/社区仿真接入单独验收但仍属于本方案的中期主系统交付，不得以动画或历史回放替代真实执行。所有任务族和所有仿真平台是研究候选范围，不等于必须全部在中期实现。

LLM 实验区不得用“已集成”一个标签混合历史档案、单问题实验和多问题统一演化。P5 跨任务统一生成系统单列建设与验收，不以它尚未完成阻断路径主系统的独立签收，也不能把主系统签收等同 P5 完成；若中期宣称其完成，须至少两个支持任务共用生成、演化、独立评价和日志入口并真实运行。尚未通过时如实列缺口，不自动降成静态展示验收。

发布矩阵每行记录需求 ID、支持合同、实现入口、验收用例、通过条件、证据 ID 和状态。签收分为产品闭环、正式基线、推荐研究结论、仿真执行、生成系统整合五栏，互不冲抵。暂无中期日期不阻止冻结这些行为标准。

### 作业、隔离和故障约定

- 执行状态、候选合法性、检查状态、证据完整性和仿真状态分开记录；超时可能保留合法候选，不等于数学无解。
- 逻辑 run 对应一个或多个可追溯 attempt。重启先核对实际执行状态；未知就标未知，不盲目重投。没有 checkpoint 不承诺断点续算。
- 取消要确认进程树停止或明确未知；如实标未知只通过状态真实性检查，不算停止/回收验收通过，取消完成必须有执行侧确认。迟到结果不得覆盖终态；原失败、运行登记和预算不能因重试删除。取消宽限、心跳、资源限额须在执行前按目标环境冻结。
- 调度层先使用验证过的单队列，或另行验证独立进程并发；不能突破现有同监督器并发禁令。
- Web 端只提交注册算法 ID 与经过 schema 验证的参数，不接收任意 shell/路径。生成候选必须另设验证过的隔离域，限制目录、网络、资源和进程；现有监督器不等于安全沙箱。隔离未通过时禁用任意候选执行。

### 仿真和安装约定

仿真须冻结上游版本、模型、世界、任务、单位映射、坐标转换、步长、重置和随机种子。分别保存访问顺序、项目几何路径、下游导航重规划和实际轨迹；交给默认导航器访问点，不等于执行了项目的原几何路径。成功必须含约定服务事件；未监测碰撞不得显示“零碰撞”。

安装包须区分核心、仿真、在线模型依赖。已有 Linux x86_64/Python 3.12 求解器依赖不能证明 Ubuntu 22.04 全栈已可离线安装。干净等价环境须验证安装、启动、运行、检查、导出、停止和重启；断网时核心承诺照常可用，在线生成明确不可用，不暗中切付费服务。

### 多 AI 接口准入

交接须携带基底 commit、schema_version、protocol_id、execution_purpose、release_id、attempt_id、模块所有权、输入输出样例、测试证据、依赖许可和已知失败。集成以合同测试和同一个真实 run 的贯通为准，不以“各自已经完成”或多数 AI 意见为准。导出转移到新目录后重做完整性与独立评分，并测试缺件和篡改检测。

## 9. 行为验收测试


以下是验收行为，不是以样例数量限制正式研究规模。SYS-01—14、17—20 对应主系统；SYS-15 对应启用生成候选执行时的安全门，未过则必须禁用该执行域；SYS-16 对应 P5 跨任务整合的独立签收门。每项需记录发布commit、环境、测试输入、预期、实际、日志和证据ID。门槛中的时间/资源/误差数值在执行前冻结。

| ID | 操作/故障 | 通过条件 |
|---|---|---|
| SYS-01 | 干净环境安装并真实求解一个受支持实例 | 不依赖原开发目录；产生新run和真实工作进程证据；独立评分、二维结果和导出闭环完成 |
| SYS-02 | 导入合法、格式错、超限、未知约束、非有限数输入 | 合法输入保留原哈希；其他明确拒绝；不静默删约束、改单位或写半份记录 |
| SYS-03 | 推荐、手动覆盖、不支持任务、模型不可用 | 实际算法与提交快照一致；类型/理由/版本可见；拒判与回退明确；无伪造置信度 |
| SYS-04 | 同一提交双击、响应丢失后重发 | 同一幂等键只有一个逻辑作业；返回可核对状态；不新建未知重复运行 |
| SYS-05 | 排队取消、运行中取消、取消与完成同时发生 | 取消完成有执行侧停止确认，无孤儿进程与迟到覆盖；未知状态如实显示但不视为停止验收通过 |
| SYS-06 | 浏览器刷新、API重启、worker被终止 | 历史与运行快照持久；恢复时核对真实执行状态；重试有新attempt且旧失败不消失 |
| SYS-07 | 超时但有合法checkpoint、超时无候选、迟到checkpoint | 执行终止原因与候选合法性独立；只接受协议允许的截止前证据；不等同于数学无解 |
| SYS-08 | 并发请求、队列满、内存/磁盘/日志超限 | 已定义限额与可诊断拒绝；无登记竞争、交叉输出或资源失控；不突破现runner单监督器限制 |
| SYS-09 | 低价伪造、漏点、重复、超载、距离错、检查器崩溃 | 错误被独立检查识别；检查异常不计可行；界面与报告不得用原自报价排名 |
| SYS-10 | 读取当前CVRPLIB结果，另加同名旧档案和不同合同 | 身份不串线；正确适配新runner记录；不同合同/预算不能混榜；失败与未启动分母保留 |
| SYS-11 | 连续切换run/revision/车辆，刷新及读取缺失/非法候选 | 路线、指标、单位和证据同源；无旧请求覆盖；null不画成0；非法候选不呈现成功样式 |
| SYS-12 | 新运行、历史回放、设计预览分别打开 | 模式醒目、日期真实；回放不触发计算；预览不进入已验收能力清单 |
| SYS-13 | 现成仿真环境启动、重置、执行、回收轨迹 | 有任务ID、版本、真实反馈和终态；访问顺序/几何路径/实际轨迹区别明确 |
| SYS-14 | 仿真重规划、漏服务、碰撞、越界、断线 | 路径替换有记录；任务未完成不得显示成功；缺观测标未知；其他核心模块仍可用 |
| SYS-15 | 生成候选语法错、非法访问、无限循环、异常输出 | 被拒绝或在已验证隔离环境受限终止；没有凭证/无关文件泄漏；失败与预算入账 |
| SYS-16 | 如果承诺P5：两个任务使用同一生成—演化—评测入口 | 共用接口与追溯链实际运行；各自独立检查；不以两个历史页面或两套脚本代替 |
| SYS-17 | 断网、在线模型故障、仿真依赖缺失 | 核心离线承诺可用；其他能力准确降级；不伪装调用成功或擅自切付费接口 |
| SYS-18 | 导出后移到新目录，断开原路径，再篡改一个文件 | 可读取并独立重评；哈希或依赖缺失被定位；不依赖私有临时链接；无凭证进入包 |
| SYS-19 | 一个AI交付前端、另一个交付后端和checker后集成 | schema和样例兼容；同一真实run端到端通过；对接口变更明确报错而非静默猜字段 |
| SYS-20 | 从正式计划汇总完整批次并导出 | 已计划、未启动、失败、合法候选分母一致；报告数字可逐项追溯；验收运行未被改名为正式实验 |
