## 课题与现有系统

课题是面向农业机器人任务的路径规划算法库与智能推荐研究。目前有两条实验通路：

- [CVRPLIB 数值基线](../experiments/baselines/cvrp/README.md)：比较容量约束路径算法的解质量与运行表现。
- 农业工作台：连接任务输入、算法建议与求解、独立验算、二维显示、已适配车型的 ROS 2 / Gazebo 执行和证据导出。

两条通路分别执行、记录和验算。CVRP 基准提供访问顺序及未标定坐标；农业机器人执行还需要米制轨迹、车辆适配和作业验证。

工作台入口为 `http://127.0.0.1:4100/`。首页是农业任务，`#/jobs` 是独立的 CVRP 数值任务，`#/bpp` 是历史装箱资料。操作步骤与适用条件见 [工作台使用说明](../setup/README.md)。

## CVRP 算法基线

[冻结主计划](../protocol/formal_plan.json)包含 17 个配置，配置数与算法家族数分别统计。正式规模为：

**17 配置 × 53 问题 × 5 种子/重复 = 4505 项。**

53 个问题来自 51 个几何与需求底本，后续数据划分需将同底本实例归为一组。归档重审记录了 **4316 项独立验算可行、189 项无有效解**。“无有效解”指本次运行未得到有效解，不能据此判定问题在数学上不可行。

PyVRP 在本计划内 **265/265 可行**，可作为固定强基线。该结果对应本计划的实例和预算，其他预算及农业任务仍需分别评估。详细结果见 [基线报告](../experiments/baselines/cvrp/results/基线实验报告.md)、[2026-10-17 归档重审](../protocol/audits/20261017/README.md)和 [算法清单](../algorithm_inventory.md)。

以下批次的目的、预算和版本不同，分别统计：

| 批次 | 规模与记录 |
|---|---|
| 冻结主计划 | 4505 项 |
| AILS-II / SISR 补充实验 | [vendor 120 项](../experiments/baselines/cvrp/evidence/vendor_all120_audit.json) |
| 接手验收 | [742 项，以及旧版、新版各 48 项](../experiments/baselines/cvrp/handoff/20261016-liyueying/核验与接手.md) |

补充实验保留各自的统计结果，不并入主计划分母。

## 智能推荐结果

[冻结模型](../src/lab/models/cvrp-knn-v1.json)对应的选择器实验包含 **120 个实例：训练 60、校准 30、测试 30**。这是独立于早期 [24 个合成实例 CRC 离线回放](../src/research/docs/RESEARCH_ACCEPTANCE.md)的一批实验。

按候选成本严格比较：

| 数据划分 | PyVRP 更优 | 成本相同 | OR-Tools 更优 |
|---|---:|---:|---:|
| 训练集，60 例 | 51 | 9 | 0 |
| 校准集，30 例 | 23 | 7 | 0 |
| 测试集，30 例 | 27 | 3 | 0 |

测试集中，PyVRP 已达到候选池的逐例最低成本。模型经正常门控后仍全部选择 PyVRP，替代选择 **0 次**，相对固定 PyVRP 的平均收益为 **0**。本次实验得到的是可运行的选择器原型和未取得增益的结果，结论限于这批实例、预算和候选算法。

### 评估设置

- 每算法 **0.25 秒、两次重复**。
- 训练目标为**未取整欧氏距离**；取整距离输入尚无对应的学习策略验证。
- 工作台默认求解设置为 **3 秒、种子 42**，该设置下的推荐收益尚未验证。

2026-10-19 的修复已将预算与距离目标的适用范围纳入推荐流程，条件不匹配时使用规则，见 [交付复核](../setup/2026-10-19/delivery-review/REPORT.md)。工作台仍支持求解与人工算法对比。

[集成报告的选择器条目](../setup/2026-10-15/integration/REPORT.md)和 [证据哈希清单](../setup/2026-10-15/integration/extended/manifest-sha256.json)指向原始 `selector-study`。完整实验包位于发布附件，Git 树内保留模型文件；复算实验需要取回原始包。

## 农业与系统实验

### 场景与车辆

研究已使用真实来源的田块轮廓，点位、需求和作业语义仍多为合成数据或代理。现有“访问并停留”任务验证的是到达与停留行为，采样、喷洒和采摘质量尚未验证。

农业工作台已完成实际运行的仿真闭环。物理执行目前限于已适配的同构差速模型，异构与曲率规划方案仍需逐类完成车辆适配和执行验收。见 [工作台说明](../setup/README.md)及 [2026-10-18 规划集成](../setup/2026-10-18/planning-integration/summary.json)。

### 多车调度与覆盖

多车物理执行采用整段任务的**串行预约**。规划阶段的并行 makespan 与包含排队、停车接驳和轨迹跟踪的实际工期分别统计；串行预约是当前执行基线。

Fields2Cover 完整路径修复后的示例中，内缩作业区覆盖率为 **100%**，全田覆盖率为 **45.83%**。两者分母不同：全田面积包含任务约定排除的地头，覆盖任务按内缩作业区验算。修复后完整路线的物理复验仍待补充。见 [规划集成原始汇总](../setup/2026-10-18/planning-integration/summary.json)。

### 地面风险与故障测试

系统已有摩擦、合成定位、有界力矩、实际轮关节反馈及故障测试。这些仿真模型尚未按真实土壤和电机标定。

[地面风险审计](../setup/2026-10-18/ground-risk-audit/summary.json)包含 13 场正常、压力、故障注入和生命周期用例，其中 8 场状态为 `succeeded`。由于用例混合了不同测试目的，**8/13 不作为正常任务成功率**。取消、正确拒绝和清理通过按各自测试目标记录，与任务完成分别统计。

### 平台与镜像

[平台快照](../setup/2026-10-18/platform-snapshot/summary.json)镜像基于 `ddb5113e…`，与源码审查提交 `23fafe4…` 分别记录。warehouse 同场景下，容器结果为 **0/5**，原生环境为 **5/5**；容器 GUI 也仍有使用限制。

## 主基线的环境证据

4505 项主基线记录的环境证据分为三部分：

| 记录 | 数量 | 环境证据状态 |
|---|---:|---|
| cloud seed0 | 901 | 具备归档意义上的 VERIFIED 链 |
| cloud seed2 | 901 | 有 host manifest，状态尚未 VERIFIED |
| 本机 seed1/3/4 | 2703 | 有与结果哈希绑定的 FROZEN resource manifest，尚缺原汇总引用的主机与环境核验包装 |

后两部分共 **3604 项**，原始结果仍然存在。路线质量、成本和描述性汇总可继续使用；已验证的同条件耗时配对需按证据完整程度缩小范围。原报告没有进行跨硬件速度排名。

后续优先追回并核验原有包装；无法找回的记录保留现有证据等级和原始内容。详见 [归档重审](../protocol/audits/20261017/README.md)。

## 演示与下一步

演示建议固定一份提交和运行环境，选用已支持车型的农业例子，依次展示：

1. 任务输入与算法建议。
2. 求解结果及 `check.valid` 独立验算。
3. 二维方案与物理执行。
4. 结果和证据导出。
5. 4505 项主基线，以及选择器未取得收益的测试结果。

有效解以独立检查通过为准，任务 `done` 和页面动画只反映运行或显示状态。演示期间保持代码版本不变，每个网关使用独立运行库。源码身份、执行互斥等修复及回归记录见 [交付复核](../setup/2026-10-19/delivery-review/REPORT.md)，物理演示仍按相应场景的验收条件准备。

后续按 [下一阶段](下一阶段.md)推进：

- **研究选择收益**：先在开发数据中检查候选算法互补性，按底本或田块分组，预先冻结新测试集；评估计入特征计算、算法选择、求解和回退的全部成本。
- **研究农业作业**：先定义服务要求和车辆约束，再补齐覆盖路线修复后的规划、独立验算和实际轨迹复验。

论文命题应从上述方向中明确选择。历史结果、失败记录和不同实验批次继续分别保留。
