# 研究结果验收

研究模块的输出需要同时保留输入身份、求解结果、独立验算和全部计划运行的状态。算法推荐依据有效的比较数据选择候选，再调用具体求解器；推荐理由和仿真画面都不能替代可行性检查。

## 输入与验算

转弯服务图使用非负整数节点和客户编号、非负整数弧成本与转向罚值。客户编号必须唯一，同一个位置可以有多个独立服务客户。经过客户位置不代表完成服务，服务事件必须逐项出现；服务完成后仍保留进入该位置时的航向。

独立检查器读取原图与路线见证，重新计算每条弧、每个转向和每辆车的载荷，检查恰好服务一次及总成本。布尔值不能代替整数编号，重复弧、重复客户编号和畸形路线均会被拒绝。`valid` 说明见证满足可行性及成本合同；最优性结论还需要原图 oracle 或其他独立依据。

候选分配中出现无入弧或不可达客户时，接口返回 `no_turn_feasible_realization`。同一位置的多个客户会作为不同的服务状态进入原图 oracle，不能通过字典覆盖丢弃其中任意客户。

## 全部计划运行的记账

| 结果 | 记录规则 |
|---|---|
| 成功或预算内已有可行解 | 保留路线、独立重算成本及收到候选的时间 |
| 解析失败、基础设施失败、超时或无解 | 保留对应运行状态，成本写为 `null` |
| 已声明但未启动 | 保留在计划分母中，单独列出数量与身份 |
| 重复运行键 | 拒绝重复计数，失败尝试同样占用原运行键 |

转弯面板回放在输出目录持续更新 `plan_accounting.json`，包含 `planned`、`attempted`、`not_started`、`not_started_ids`、`terminal_counts`、`completed_rate_planned` 和 `mode_valid_rate_planned`。即使总时限导致提前停止，未启动任务仍会保留在分母中。原有 `summary.json` 继续保持历史回放格式，其中 `total` 是已有记录数；计划完成率应读取上述记账文件。

CVRPLIB 汇总拒绝状态与可行性互相矛盾、非有限或非整数成本、以及重复 `run_key`。`available_mean_cost` 仅代表有效结果子集；任何计划任务失败或未启动时，不提供整个计划的平均成本。

`run-one` 遇到监督器 `RuntimeError` 时也会保存 `INFRA_ERROR`，保留算法、种子、预算、载荷哈希与已占用运行键。运行前后的求解源代码哈希不同，该次运行不能作为有效比较结果。

## 推荐选择与数据划分

历史 CVRP 性能矩阵只接收已经通过验算和预算检查的完整记录，不能先删除失败行再计算均值。同一性能单元内的求解种子不能重复。

训练只使用训练分区的性能数据和缩放参数。清单提供 `base_id` 或 `parent_instance_id` 时，同源实例必须处于同一 replicate，不能跨训练、校准和测试分区。该检查依赖正确的母实例标注；不同文件名本身不能证明数据独立。按实例划分的结果也不能直接表述为跨场景族泛化。

CRC 参数要求 `0 < alpha < 1`，校准损失必须为布尔值，排序分数与阈值必须有限且非负。排序分数表示预测成本差，不是分类概率。六个校准实例对应修正下限 `1/7`，因此主设置 `alpha=0.10` 的全部回退是既有小样本合同的结果。

单客户、客户同点及全部几何成本为零的输入使用有限特征。无客户间距离或无空间跨度时，相应比值记为零；零几何上界只允许零路线成本，不能用来归一化正成本。零预测成本之间的排序差记为零。

## 回归检查

在 `src/research` 执行：

```sh
python3 scripts/test.py
```

回归覆盖整数编号别名、畸形见证、同点多服务、不可达客户、CRC 非法参数、同源分区泄漏、重复运行键、基础设施失败持久化、提前停止和坏输入的完整计划记账。合成检查用于验证实现合同，正式性能结论仍需要固定实例、预算、种子和完整失败记录的基线实验。
