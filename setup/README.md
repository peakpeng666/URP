# URP 科研面板：本机唯一使用入口

已打通真实的「场景 → 推荐 → 求解 → 独立检查 → 二维路线 → TB4 仿真 → 实际轨迹 → 导出 → 关闭」流程。先使用 **官方迷宫 · 双点巡检闭环**；仓库货架是作物行的代理，不能视为农业环境验证。验收数据、故障记录与限制见 [集成验收报告](2026-10-15/integration/REPORT.md)。

## 启动与停止

在项目根目录运行（复用现有环境，不需要 sudo）：

```bash
bash setup/run.sh lab --open
```

访问 **http://127.0.0.1:4100/**。网关自动检查并构建更新后的前端；档案后端随网关管理，ROS 会话按需启动。无需另开前端/后端命令。重复执行入口会提示已有网关；不要同时启动旧导航诊断脚本。

- 仿真页的「关闭仿真」只关闭本次仿真，保留面板及记录。
- 在启动终端按一次 Ctrl+C，或在另一个终端执行 `bash setup/run.sh lab-stop`，有序关闭整个面板及其拥有的服务。关闭期间等待完成；极端故障的清理可能需要约 2.5 分钟。
- 失败后先查看页面原因和日志，等清理完成、会话显示「未运行」或「失败」，再「启动所选场景」。网关意外中断时重新运行同一入口，会恢复保存的记录；仅接管带 URP 会话归属标记的进程。端口被未知程序占用会报错，请勿用 `pkill` 批量关闭 ROS。

## 可重复的演示（约 1–2 分钟）

1. 首页进入「规划」，选择默认 **官方迷宫 · 双点巡检闭环**。它包含两个巡检点、一个起点和 4.30 m 往返几何路径。坐标为 map 米；成本为厘米加转弯惩罚。
2. 查看规则推荐，选择「转弯模式分层 DP」，时间预算 3 s、种子 42。「求解并独立检查」后，应显示最优成本 **490 cm_equivalent**，独立检查与整段路径占用检查通过。
3. 「进入仿真」，勾选需要的 Gazebo/RViz 原生窗口，点击「启动所选场景」，等待脱座、定位和 Nav2 就绪。图形窗口可选，二维页面始终可用。
4. 保持「AMCL 传感器定位」，选择「几何路径跟踪（FollowPath）」后执行。页面显示计划路径、Gazebo 实际轨迹、顺序到达进度及误差。成功要求 2/2 到达，跟踪最大偏差和各段端点误差不超过 0.35 m；不是零误差逐点重放。
5. 「导出实验 JSON」保存实际轨迹、动作状态和指标；规划页可导出输入、算法版本、参数、原始结果与检查报告。可改用「Nav2 逐点导航」再次执行，它保留访问顺序，允许 Nav2 重新规划路径。
6. 「关闭仿真」，确认关闭完成。运行记录与日志保留，可从「运行记录」回看当时输入快照。

规划页可直接编辑任务、需求、容量，或开启地图点选；高级输入仍有 JSON 编辑器。先更新推荐，再求解。运行记录支持筛选、同实例多算法对比与 CSV/JSON 导出；实例哈希或单位不同会明确提示不可直接比较。无量纲基准算例不能送入仿真。

## 扩展演示

- **仓储货架通道 · 作物行代理**：默认五任务，选择转弯模式分层 DP，成本 6496 cm_equivalent、几何长度 58.96 m。AMCL 定位下，路径跟踪和 Nav2 逐点导航分别约 5 分钟；后者会重新规划，长度不可冒充原算法执行长度。
- **车间空地 · 内缩作业区覆盖**：选择 Fields2Cover boustrophedon，保留地头 0.8 m、幅宽 0.5 m、规划最小转弯半径 0.3 m，得到 5 条作业行及 Dubins 连接，计划 27.742 m。地头改为 0.6 m 时会因足迹越界拒绝，不是求解器证明数学上无解。恢复 0.8 m 后重新求解再进入仿真。覆盖任务使用内缩作业区覆盖率和实际足迹验收，不使用访问任务计数。TB4 允许原地转向，不代表真实农业车辆运动学验证。
- **欧氏 CVRP 基准**：支持 PyVRP/OR-Tools 真实求解。学习原型仅在明确范围内显示，附 60/30/30 独立拆分的评估证据；30 个测试实例均选择固定 PyVRP，平均增益为 0。改变 0.25 s 预算或实例分布后不适用原评估，范围外回退规则。它不是恢复后的历史研究结果。

## 数据、依赖与排错

- 运行数据：`src/lab/runtime/lab.sqlite3`；求解原始输入/输出/退出码：`runtime/runs/<run_id>/`；ROS 原始日志和清理报告：`runtime/sim/<session_id>/`。不要删除它们来掩盖失败。
- 环境：求解器 Python 3.12 独立 uv 环境；ROS 使用系统 Python 3.10；不更换系统 Python。已有依赖正常时不需重装；需要恢复锁定依赖时执行 `bash setup/run.sh lab-setup`（uv.lock + package-lock.json）。官方 ROS/Fuel/native 依赖由报告中的指纹校验。
- Fuel 缓存：`setup/2026-10-15/cache/ignition-fuel`。启动前检查所选世界的实际依赖，缺模型/网格/使用中的贴图时明确报错。审计命令：`cd src/lab && .venv/bin/python -m urp_lab.worlds warehouse`。
- Fields2Cover 是可选模块，复用已有 wheel 并锁定二进制指纹；支持单个凸作业区，独立检查离散曲率和整段足迹。缺失或指纹不符会显示原因，Shapely 基线仍可用。原 wheel 的 C++ 构建来源未完全恢复，不能宣称从源码逐位重建。历史 BPP 原始归档缺失仍显示空数据。
- `parameter_bridge` 默认使用有指纹约束的 `_exit(main返回码)` 临时兼容措施，**未修复/定位堆损坏根因**。`URP_BRIDGE_FIX=0` 可关闭以受控复现。另有 `URP_TF_FIX=0`、`URP_GUI_FIX=0`，只影响本次相应子进程；没有替换系统库或全局预加载。

开发者接口见 [CONTRACT](../src/lab/CONTRACT.md)。旧 [部署报告](2026-10-15/deployment/REPORT.md) 与 `navigation` 命令保留作历史诊断，不是第二套使用入口。
