# 资产库与科研图表 · 验收记录（2026-10-16）

本轮在现有工作台上新增：统一资产库（地图 / 车辆 / 障碍物与设施 / 场景模板）、资产进入任务规划的完整链路（底图、车队、设施）、实验结果 / 决策记录 / 仿真回放三个面板，以及按期刊版式输出的科研图表引擎。没有重写求解器，没有修改另一方维护的 ROS 后端文件。所有数字来自本机真实运行记录；截图在 `assets/evidence/`，图表在 `figures/`。

## 入口

| 入口 | 位置 |
|---|---|
| 资产库工作区 | 顶栏「资产库」，或 http://127.0.0.1:4100/#/assets（`#/assets/<资产 id>` 直接打开某个资产） |
| 导入资产 | 资产库「导入」或把文件 / 文件夹拖进资产库；⌘K「导入资产」 |
| 用地图新建任务地图 | 资产检查器「用此地图新建任务地图」 |
| 资产进入当前任务地图 | 车辆「用于当前任务地图车队」；设施「放进当前任务地图」；标定图片「设为当前任务地图底图」；任务规划 → 检查器 → 车队 →「车辆资产」 |
| 实验结果 / 仿真回放 / 科研图表 | 任务规划底部标签；「决策记录」在右侧推荐面板旁；「科研图表」也在算法实验工作区 |
| 接口 | `/lab/api/assets/*`（资产），`/lab/api/figures/{presets,catalog,render/<key>,meta/<key>,bundle}`（图表） |

## 支持的资产与场景范围

| 类别 | 格式 | 处理 |
|---|---|---|
| 地图 · ROS 栅格 | YAML + PGM / PNG（trinary / scale / raw，negate，占据 / 空闲阈值） | 按 Nav2 map_server 语义判读；像素角点仿射（第 0 行在上）；分辨率 / 原点 / yaw 可改并在服务端重算；确认坐标后才能锁定或建任务地图；OpenCV 轮廓提取可通行边界与障碍（未知区按障碍或可通行可选） |
| 地图 · 矢量 | GeoJSON（RFC 7946 经纬度、旧式 `crs` 成员、投影坐标） | 经纬度按质心选 UTM 带换算为米，保留孔洞与属性；未知投影坐标必须确认“已是米”才继续；按属性识别边界 / 地块 / 道路 / 地头 / 禁行区 / 障碍 / 任务点 / 车库 / 卸货点 |
| 地图 · 图片 | PNG / JPG | 只作背景、永远不可通行；已知距离或控制点标定（相似变换 / 最小二乘仿射，逐点残差与 RMSE） |
| 地图 · Gazebo 世界 | SDF world（含本机 TurtleBot4 世界） | 只作仿真参考，不自动变成规划几何 |
| 车辆 / 设施 | glTF / GLB（浏览器内 Khronos glTF-Validator）、STL / OBJ / DAE、URDF（含网格与 `package://`）、SDF 模型、本机 ROS 描述包（Xacro 在本机展开）、Gazebo Fuel 缓存 | 三级能力：显示（朝向 / 缩放确认）、规划（足迹 / 容量或“不载货” / 车速 / 运动学 / 最小转弯半径 / 作业幅宽）、仿真（碰撞 / 惯性 / 驱动 / ROS 接口 / 适配）；外观、足迹、碰撞几何分层预览 |
| 场景模板 | 任务地图另存为模板 | 实例化为新的“我的场景”，保留资产引用 |

安全：导入只读取与解压，不执行任何脚本；上传的 Xacro 拒绝；压缩包拒绝路径穿越、符号链接、加密成员与压缩炸弹（大小 / 文件数 / 压缩比上限）；外部网址与绝对路径引用被阻止；上传必须带应用自己的请求头，网关拒绝其他来源。版本：锁定后的版本不可改，修改生成新版本；被场景或运行记录引用的资产不能删除；每个版本有基于原始文件的 SHA-256。

## 验收 1：导入地图 → 确认坐标 → 编辑农业任务 → 保存并重新打开

1. 导入 `assets/inputs/nl_field_1.geojson`（Fields2Benchmark 荷兰田块，CC-BY-SA-4.0，doi:10.5281/zenodo.14524735）。检查结果：RFC 7946 经纬度 → EPSG:32631（UTM 31N），局部原点 (690451.33, 5879635.75)，330.9 m × 306.4 m，1 个边界要素。填写许可、署名、DOI 后保存为 `map-nl-1-fields2benchmark-f71197` v1（sha256 5cbfadd84dbc…）。〔01、02〕
2. 坐标未确认时「用此地图新建任务地图」不可用；在预览里核对后确认。〔03〕
3. 新建任务地图：边界 28 个顶点；车库按车体半径自动建议在离西南角最近的可通行点；以种子 2026 在可通行区生成 30 个任务点；车队选内置田间差速机器人。〔04、05〕
4. 创建 `tm-mvaqwzip-ni0` 并在任务规划中打开（底图、推荐、车辆资产区齐全）。〔06〕编辑：画地块「A 区」，作物“葡萄”、作物行斜向 45°；添加任务点 31；自动保存。〔07〕
5. 整页刷新后重新读取：地块 / 作物 / 行向、31 个任务点、资产引用（地图 v1 与车辆 v2 及其哈希）、车队绑定、矢量底图、坐标系说明“EPSG:32631 局部，原点 …”全部保留。〔08〕

另：导入 TB4 仓库栅格（`warehouse.yaml/.pgm`）：0.03 m/像素，原点 (−15.1, −25, 0)，1006 × 1674 像素 = 30.18 × 50.22 m，空闲阈值 0.1；确认后提取可通行区 1279.49 m²、27 个障碍、826 个顶点，并如实注明“另有 322 块与主区域不连通的空闲区未纳入”。〔23〕图片标定工具（已知距离 / 控制点）本轮未在浏览器里逐步操作，标定算法由后端单元测试覆盖。

## 验收 2：导入车辆展示资产 → 配置为规划车辆 → 仿真兼容性

1. 导入 `CesiumMilkTruck.glb`（Cesium 2017，CC-BY-4.0，Khronos glTF Sample Assets）。Khronos glTF-Validator：0 错误、0 警告；包围盒 2.792 × 2.653 × 4.869（模型坐标）。〔17〕
2. 三维预览中核对：车头格栅与机器人前进方向（红轴 +x）一致，模型前方 +z、向上 +y，确认朝向与尺寸。〔18、19〕
3. 规划参数：足迹取已确认的包围盒 4.869 m × 2.792 m，容量 20，车速 1.2 m/s，阿克曼转向，最小转弯半径 5.5 m → 等级“可规划”。检查器写明求解器实际读取的值（车体半径 2.807 m）与未参与规划的项（矩形朝向、转弯半径）。
4. 仿真层逐项列出缺失：碰撞几何、惯性、驱动控制器、ROS 2 接口、工作台仿真适配；两个适配都标为不兼容并给出原因。
5. 用于原来的窄田块：服务端校验拒绝保存（车库离边界不足 2.807 m），地图上出现醒目提示（本轮新增）。从同一地图新建任务地图并选这辆车：车库按 2.807 m 净空重新建议，生成 20 个任务点。〔20〕求解：PyVRP 822.5 m、节约算法 829.7 m、OR-Tools 1358.1 m，均通过验算。
6. 点 Gazebo 执行：在发出任何请求之前拒绝，并说明“田间仿真不能生成该车型：没有能生成这辆车的仿真适配（缺项见资产检查器）”。〔21〕

## 验收 3：兼容车辆 → 求解、验算、执行、回放、导出

1. `tm-mvaqwzip-ni0` + 内置田间差速机器人。求解：OR-Tools 车队调度（最晚完成 681 s，1671.8 m）、PyVRP（1354.2 m，755 s）、节约算法 + 2-opt（1355.5 m，756 s）。〔09〕独立验算全部通过。〔10〕
2. 执行中发现并修复：车体半径按毫米四舍五入成 0.488 m，小于仿真车体外接圆 0.4883 m，后端拒绝执行；现改为向上取整（0.489 m），重新绑定、求解后执行。
3. Gazebo 会话 `field_20261016T091332_d88bd1`：31/31 个任务点到达；最晚完成 11 min 21 s → 11 min 30 s（+1.3%）；总里程 1671.8 → 1674.8 m（+0.2%）；横向偏差均值 0.003 m、最大 0.15 m；实际倍速约 3.9×。〔11〕
4. 回放（任务地图上）：规划路线、真值轨迹、车体足迹、任务到达状态随时间轴变化，可按车辆筛选。异常定位：车 2 与车 3 在 t = 691 s 于共用车库附近相距 0.11 m（仿真屏蔽车间碰撞且不做避让，多车避碰标为“未验收”）。〔12〕
5. 实验结果面板：完成率（写明分母）、里程、时间、趟数 / 返库与载重、约束违规、覆盖率（多车任务不适用）、跟踪误差、多车避碰状态。〔13〕导出实验记录（JSON，19 KB，`agri-workbench.experiment-record/1`）：场景、资产版本、提交时的决策快照（rules-v2 推荐 OR-Tools，实际提交 OR-Tools）、运行参数与复现信息、仿真指标与派生异常、验收状态、原始导出链接。
6. 决策记录：输入特征 → 候选与得分 → 推荐 → 学习型选择器状态（“不适用于此问题类型”，不冒充模型预测）→ 实际选择 → 效果对比。〔14〕

## 验收 4：异常情况

| 情况 | 结果 |
|---|---|
| 截断的 GLB | 阻止保存：GLB 长度字段 369980 与文件大小 60000 不符；glTF-Validator `GLB_UNEXPECTED_END_OF_CHUNK_DATA`〔22〕 |
| 缺资源 | YAML 引用的 `missing_floor.pgm` 不存在 → 阻止保存并说明要一起导入 |
| 坏压缩包 / 路径穿越 / 无上传头 | 422 / 422（跳过并警告）/ 415（后端测试） |
| 上传 Xacro | 拒绝（会执行宏），提示先展开或引用本机描述包 |
| 不适用 / 不存在的算法 | `A* 不适用于 fleet_routing 场景`，`没有算法 no.such.solver` |
| 无解 | 单趟、1 台车、容量 5、20 个任务点：三个算法都“不可行”，原因“总需求 20 超过车队单趟总容量 1 × 5”；检查器同时提示与车辆资产容量不一致〔24〕 |
| 车体过大 | 服务端校验拒绝保存，地图顶部显示原因 |
| 服务断开 | 状态栏“服务断开”；离线修改保留在本地并提示“服务恢复后会自动重试保存”〔25〕；网关恢复后自动保存成功（服务器任务点 20 → 21） |

## 科研图表（期刊版式）

引擎在服务端用 matplotlib 绘制，只用工作台记录的真实运行、仿真与课题数据；缺数据的图不画并说明原因。

- **21 种图**：任务地图、地图 → 规划几何、多车路线、每车工作量、车辆时间线、多方案路线对照、算法结果与计算时间、求解收敛过程、性能曲线（Dolan & Moré）、差距分布、临界差图（Friedman + Nemenyi，Demšar）、两两检验（Wilcoxon–Holm）、差距随时间（中位数）、时间–质量权衡、实例空间、推荐 vs 单一最佳 vs 理想选择（AS / SBS / VBS，闭合差距）、仿真轨迹与规划路线（含最大偏差处放大与车体）、规划 vs 执行、路径跟踪误差（ECDF + 均值 / P95 / 最大）、车间最小距离、任务完成进度。
- **版式**：Elsevier 90 / 140 / 190 mm、IEEE 88.9 / 181.9 mm、Springer 84 / 174 mm、学位论文 120–150 mm（宋体 / Times 风格）；宽度精确到栏宽，只裁高度。正文 7.5–9 pt；中文坐标轴用“量/单位”（GB/T 3102），英文用 “Quantity (unit)”；Okabe–Ito 色盲友好配色 + 标记 / 线型冗余编码，同一算法在所有图中颜色、标记、线型一致；地图有比例坐标，UTM 坐标系加指北针。
- **格式**：PDF / EPS（TrueType Type 42 内嵌，无 Type 3）、SVG（文字可编辑）、PNG / TIFF（默认 600 dpi，可选 300 / 1200，TIFF 为 LZW）。核验：IEEE 单栏 PNG / TIFF 宽 2100 像素 = 88.9 mm @ 600 dpi，EPS 边界框 252 pt。
- **论文图包**：图（矢量 + 位图）、每张图的源数据 CSV、中英图注（含样本量、统计方法、数据来源）、`manifest.json`（版式、软件版本、场景 / 方案 / 仿真 / 课题 / 资产版本与数据指纹）。本次生成：`figures/figures_elsevier_en.zip`、`figures/figures_thesis_zh.zip`（各 21 张图、25 个源数据 CSV），预览 PNG 与图注在 `figures/preview_en/`、`figures/preview_zh/`。
- **数据可比性**：求解过程轨迹只有在终值等于该运行目标值时才画（“尽快完成”任务里 PyVRP 记录的是内部的总里程目标，终值 1354.21 ≠ 最晚完成 754.94 s）；收敛图与“差距随时间”图把被排除的运行写进图注。该规则同时修正了「统计分析」面板的同一曲线。
- **课题数据**：`study_20261016T085916_949c`——8 张由文字生成的农业任务地图 × 5 个多车算法 × 3 个种子（随机算法），2 s 预算，88 次运行。这是验证图表管线的小样本真实实验，不作为论文结论。

## 测试

后端 `pytest` 127 项（含新增资产 13 项、图表 6 项）、前端 `tsc`、`vitest` 42 项、生产构建均通过。浏览器验收在内置浏览器中完成；部分点击在测试环境里偶发未送达，已用事件监听确认应用处理器本身正常。

## 已知限制

- 田间仿真只生成内置差速机器人；导入车型只能规划不能执行（见《后端对接需求》）。
- 多车求解只支持同构车队、单车库；不保证最小转弯半径；矩形足迹按外接圆膨胀。
- 图片标定、设施放置、场景模板实例化本轮只做了接口与界面，浏览器里未逐步走完。
- Gazebo 世界资产只作参考，不转换为规划几何。
