# 后端对接需求（资产库 / 仿真 / 求解）· 最小接口清单

前端与资产库已经把“资产 → 规划 → 执行 → 回放 → 导出”串起来，并对做不到的部分如实标注。下面这些需要维护求解器与 ROS 后端的一方配合；按优先级排列，每项写明现状、需要的接口和验收方式。

## 合并收尾更新（2026-10-17）

KIMI 前端已接入多库、异构参数、输入变更失效、真实交通证据和服务端原始记录导出。合并补齐了补给提取、图节点顺序、曲率折返、遥测缺口、能耗停车尾段、异构容量及推荐准入修复；当前模型为 fleet-model/2、energy.post_hoc/3。旧补给方案需重新求解，旧能耗记录保留版本边界。下列逐轮说明是历史状态；最终范围以 [集成报告](../2026-10-15/integration/REPORT.md) 为准。尚未交付通用车辆执行、曲率车辆执行、并行避碰、地形/土壤校准和学习推荐增益。

## 后端逐轮落实记录（原需求保留在下方）

- **1 部分完成**：已接收并核对车型引用、版本、文件哈希和提交时元数据；不一致 409，未适配车型 422。只允许真实可生成的内置差速模型，尚未实现通用 URDF / SDF 导入执行。
- **2、3 已有可验收基线**：每车独立停车位，完整任务串行预约，等待计入用时；启用车间碰撞，接触和距离保护触发全车失败停车。另做同步轨迹整段最小距离与接触流完整性检查。它是保守执行策略，尚非并行多车避碰规划器。
- **4 已完成后端（2026-10-17 第二轮）**：`vehicles.fleet` 按类别给出 `count/capacity/speed_mps/robot_radius/payload`（可带按类 `asset` 引用进入快照）；`pyvrp.fleet` 与 `ortools.fleet`（总里程与 makespan 两种目标）按类别求解，makespan 为每类车速建独立时间矩阵；每条路线带 `fleet_class/capacity/speed_mps/robot_radius`，独立检查器按各类参数复算并核对声明字段；通行图按最大足迹半径膨胀。构造基线（sweep / cluster_first / savings）明确只支持同构并报错；推荐器对异构实例不再推荐构造基线。执行边界如实标注：田间仿真仍生成同构内置差速机器人，多类别方案启动执行返回 422，不改写历史记录。前端字段规范见 [CONTRACT 6.5](../../src/lab/CONTRACT.md)。
- **9 已完成后端字段**：接触的时间/位置/车辆对、控制周期误差与指令、任务实际停留和完成时刻；区分 `row_collision_shapes`（几何数）与 `row_collisions`（观测接触数）。旧记录没有传感器证据时返回 null，不冒充零。
- **11 已完成服务端记录与内容哈希**：`GET /lab/api/runs/{id}/record` 返回完整记录及 SHA256，包含关闭报告。哈希是完整性校验，不是身份签名。现有前端按钮仍按旧格式自行拼装，未改动前端。
- **5 已完成后端（2026-10-17 第三轮，曲率约束）**：`vehicles.fleet[].min_turn_radius_m` 为正的类别用 OMPL `DubinsStateSpace`（Dubins 1957）实现曲率受约束路径——航向携带、仅前进不倒车；路线带 `min_turn_radius_m` / `curvature_radius_m`，检查器按采样三点外接圆独立复核曲率与间距；分配仍按直线图距离优化，曲线长度如实进入里程/工期指标。阿克曼/铰接资产的最小转弯半径从 solver_mapping 的"忽略"改为实际参与多车规划。边界如实标注：`travel='rows'` 的通道内曲率规划未实现（校验拒绝）；田间执行仍是可原地转向差速模型，曲率类别启动执行 422；Reeds–Shepp 倒车路径未实现。
- **10 已完成后端（2026-10-17 第四轮，记录与对照）**：TB4/Nav2 会话结果新增 `localization` 块——AMCL 估计 vs 插值真值的配对误差（位置 RMSE/分位数/最终、航向 RMSE）与 Nav2 重规划事件汇总（次数、首末时刻与路径长度；原因不推断）。时间线（`actual.amcl`、`nav2_plans`）本就逐样本保存，本轮补上对比分析并进入 API 结果与导出链路；纯记录不门控。真实会话验证：AMCL 位置 RMSE ≈ 0.04 m；follow_path 0 次重规划 vs nav2_waypoints 43 次，模式差异如实可见。
- **8 已完成后端（2026-10-17 第五轮，通行走廊）**：GeoJSON 导入识别道路 / 机耕道 / 地头要素（面要素直接、线要素按宽度缓冲成面）为 `corridors`；行间通行网络（`lanes.Network`）把走廊从种植区扣除，自动并入开阔区通行——矢量地图的道路 / 地头从"只作底图"变为通行网络输入。导出保留走廊要素，`free` 通行不受影响，旧实例无 `corridors` 行为不变。求解与独立检查均按同一网络复算。

- **6、12 仍待实现/评估**：没有据此宣称足迹朝向或学习推荐已通过。
- **物理模型补充已实现**：`fieldsim/physics` 暴露版本化刚体配置；内置模型改为官方示例的球面滚动接触抽象，总宽 0.96 m、外接圆仍约 0.4883 m。源时间姿态、轮式里程计漂移、实际物理库哈希和解析时间参考进入完整结果；旧模型绑定须重选当前内置车型后重求解，不改写历史结果。详见 [CONTRACT 6.6](../../src/lab/CONTRACT.md)。这不等于已经完成第 10 项的 AMCL 估计误差记录。

## P0 · 执行与验收的正确性

1. **按车辆资产生成仿真车体**
   - 现状：田间仿真（`POST /fieldsim`）总是生成内置 0.8 × 0.56 m 差速机器人；导入车型（如 Cesium 运奶车）只能规划，前端在发送请求前拒绝执行。
   - 需要：`POST /fieldsim` 接受 `vehicle_asset: {id, version, sha256}`，从资产版本的 URDF / SDF 读取碰撞、惯性、驱动（DiffDrive / AckermannSteering / ros2_control）生成车体；后端同样校验方案里的 `instance.fleet.asset` 与生成的车体一致，不一致时 409。
   - 验收：导入一个带 `<collision>`/`<inertial>`/驱动插件的 URDF 车辆，资产检查器“仿真”层全部满足，执行成功且结果记录车型与版本。
2. **共用车库的出发 / 返回排队**
   - 现状：各车从同一车库出发并回到同一点，验收运行中车 2 与车 3 最近相距 0.11 m（t = 691 s），10% 以上时间低于车体对角线；仿真屏蔽了车间碰撞，所以不会报错。
   - 需要：车库停车位（每车一个停车点）或错峰出发 / 返回；结果里给出各车停车点。
   - 验收：车间最小距离图在车库阶段不再低于车体对角线。
3. **多车避碰**
   - 现状：规划不建模车间冲突，执行不做避让，界面与导出都标“未验收”。
   - 需要（二选一）：规划端时空冲突检查 / 预约；或执行端碰撞监测 + 等待策略。打开车间碰撞并在结果里记录接触事件（时间、位置、车辆对）。

## P1 · 求解能力（影响哪些资产能“真正参与规划”）

4. **异构车队**：`instance.vehicles` 支持按车给出容量、车速、足迹（如 `fleet: [{asset, count}]`）；求解器与独立检查器同时支持。现状只支持同构车队，资产绑定也只能选一种车。
5. **最小转弯半径**：阿克曼 / 铰接车辆的多车路径用 Dubins / Reeds–Shepp 连接并在检查器中复核曲率；现状该项列为“未参与规划”。
6. **足迹朝向**：矩形 / 多边形足迹按朝向做碰撞检查（现状按外接圆膨胀，偏保守）。
7. **多车库与卸货 / 补给点**：GeoJSON 中的 `unload` / `supply` 语义目前只显示不规划；需要 `depots[]`、`unload_points[]` 与对应的趟次约束。
8. **地块孔洞、道路与地头作为通行网络**：矢量地图里的道路 / 地头只作底图；希望通行网络（`lanes.py`）能直接吃这些要素。

## P2 · 记录与复现

9. **仿真结果补充**：作物行接触事件的位置（现只有次数）、控制周期的横向偏差序列（现轨迹约 0.07 s 采样，在线统计最大值与记录轨迹最大值不同）、每个任务的实际作业时长。
10. **估计定位与 Nav2 重规划记录**：TurtleBot4 / Nav2 会话的结果同时保存 AMCL 估计位姿与真值、每次重规划的时间与原因，以便画“估计 vs 真值”和“跟踪 vs 重规划”的对比图。
11. **实验记录导出端点**：现在由前端拼装（场景 + 资产版本 + 决策快照 + 运行 + 仿真）；希望后端提供 `GET /runs/{id}/record`，由服务端组装并签名（哈希）。
12. **学习型选择器覆盖多车任务**：推荐快照已随每次运行保存（`recommendation_at_submission`），多车任务目前只有规则策略；课题数据可作为训练集。
